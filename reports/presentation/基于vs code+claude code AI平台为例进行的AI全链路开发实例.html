打一句指令，系统自己知道做到哪了

不需要交代背景，不需要说「上次做到哪」
1先读进度，再开口系统打开时会读该案件下 9 个进度文件，算出哪些工程已签核、有没有没处理完的指摘、下一步该做哪一件。

3换人、隔天、并行都不断线位置来自文件而不是对话记忆，谁打开看到的都一样。

八个工程不靠人记，每一步都有 prompt 模板、都有登记

每道工序都有一张标准化作业卡，卡的内容就是 prompt 模板的四要素——输入、输出形式、制约条件、合格基准；在这之上，卡还带了执行状态和人签核
✓需求理解n01
✓基本设计n02
✓详细设计n03
✓框架环境n04
✓制造n05
✓单元测试n06
✓集成测试n07
✓发布运维n08
↻变更环n09
1每步一套 prompt 模板写清输入是什么、产出写哪个文件、受哪些限制、什么算合格，四要素齐了才算一套。照模板做即可，不需要先理解整条链。
2模板之外还有状态与签核prompt 模板只管「怎么干」；做完一步，产出路径、第几步、谁签核，全部写进该工程的进度文件——状态和签核才是它成为一道工序的原因。
3下游读文件，不读记忆下一个工程从上一工程的产出继续，人换了、隔了两个月，接得上。

一条命令，六项检查：全绿才允许签核

机器能判的交给机器，判不了的（内容对不对）才留给人
1编号合法不得出现未登记编号
2追踪闭合需求↔测试双向不断链
3字段完整每份成果物必备字段不缺
4生成物一致人读版与设计项数一致
5命名分区定义层与接口层不混写
6机密零命中13 类敏感形态全扫
1一条命令扫全仓不需要人逐项翻文件。每次都跑同一套，结果可复核。
2不过就退出码非 0不是「建议」，是硬闸：不绿不能签核、不能提交。
3规矩会自己变长每次踩过的坑写成规则、再加进检查，下一次全公司自动免疫。
实现：tools/trace_check/　·　规则 .claude/rules/

读法：六项全 PASS；orphans=0＝没有断链的编号；seal_hits=0＝没有扫到机密。任何一项 FAIL 或数字不对，命令直接返回失败。

一条需求牵动多少东西，一条命令算出来

需求编号是钥匙：正向查它落到哪，反向查它是谁要求的
1只在台账里发号需求、设计、代码、测试的编号都从一处发出，不能自己编。自编的编号在自动校验时直接被判不合格。
2每件产出都写「我来自谁」台账据此生成双向追踪表：需求 → 设计 → 代码 → 测试，反着也查得回来。
3改之前先算账客户提一条修改，先算出受影响的清单和重做顺序，再决定回哪个工程——不靠人回忆，也不整条链推倒。
实现：docs/00_registry/ids.yml · traceability.yml · tools/impact

同一份机读源，自动生成正式 Excel

真源只有一份机读文件；对客交付的正是由它生成的 Excel，不手改
1一份真源，正式成书设计书只写一次，交给客户的正式 Excel 由它自动生成，列数与设计项数自动对齐；网页视图只供内部查看，不对外交付。

敏感值进不来、出不去：扫描拦截 + 脱敏还原

对日项目最容易出事的一环，做成了两道闸
1进不来：全仓扫描连接串、口令、内网地址、员工编号、业务实值等 13 类形态，写进任何文件都会被拦下，提交不了。
2出不去：外发前脱敏真要发给对方的资料，先把真值换成占位（如口令→占位、内网地址→占位），再发。
3替换是双向的对方回了修改，占位能原样还原成真值，不需要人工对照表格。
实现：.claude/rules/01-security-redlines.md　·　tools/masking/mask_demo.py
截图位 ⑥ 脱敏自检与拦截示例内容 · 可替换

一次真实验收记录里，注入一条内网地址与一条口令后，自动校验确实以失败退出——不是「提示一下」，是拦住。

问一句，返回带出处的原文片段

不是「AI 凭印象回答」，而是「哪份文件的哪一行这么说」
1先把历史资产切碎入库旧案件的设计书、代码、规则被切成片段，逐条标上案件 / 模块 / 文件 / 行号。
2检索先收窄范围先按案件、再按模块过滤，只把相关片段交出去——不把全量资料塞进去，也就不容易串味。
3每条都能点回原文答不出来就答不出来，不编。出处可查，评审时才敢用。
实现：tools/kb-platform/repo/　·　tools/rag（build / query / eval）
与平台的关系：同属「知识库管理」；接上平台后，库与检索接口改由平台统一供给
