# reports/module-survey/ — R60 历史案件模块普查（**不是框架，是附赠数据**）

> **一句话**：这是 `legacy-module-surveyor` 这个 agent 跑出来的一次性调查结果，
> 用来从 R60 的 14 个模块里挑 3 个当教材（简单 / 中等 / 复杂）。
> **它不参与 8 工程，不参与 6 道门禁，删掉也不会让任何流程坏掉。**

## 里面是什么

| 路径 | 内容 | 文件数 |
|---|---|---|
| `R60*/` ×13 | 每个模块一组调查票（YAML），5 个观察点打分，带证据行 | 221 |
| `scores/` | 13 个模块的打分汇总（每模块 1 个 YAML，与上一行一一对应） | 13 |

合计 **234 个文件**（实查：`find reports/module-survey -type f | wc -l` → `234`），
全部是 R60（`D:\AI_work`）的派生数据，不含 `D:\AI_work` 的源码原件。

## 和框架的关系

- **属于附赠层的第 5 类**：R60 专属、不是 trans-cosmos-ai 骨架的组成部分。
- 骨架的核心资产是 `.claude/` + `tools/` + `docs/00~80`；这里是**教材选题的中间产物**。
- 唯一消费者是「挑教材模块」这个动作。挑完了，它的价值就归零。

## 能不能删

**能删，代价是「再挑一次」要重跑。**

- 删除：`rm -rf reports/module-survey`。不影响 `trace_check`、不影响任何工程节点。
- 重跑：`legacy-module-surveyor` agent 需要再次读 `D:\AI_work`（**只读**）并重新普查，
  耗时较长、会花 token。
- **判断依据**：如果你已经选定教材模块、或短期内不再挑教材 → 可以删。
  如果还会扩教材、换模块 → 留着，但请连同本文件一起留着，否则下次没人知道这 234 个文件是干嘛的。

## 机密度

`internal`。内容是模块名 + 打分 + 证据行，**不含真实员工姓名、不含连接信息**。
但它描述的是他人项目的内部结构，**对外发送前仍须过 `tools/masking/mask_demo.py`**（红线⑦）。
