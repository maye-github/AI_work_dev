## 1. 適用と共通前提

### 1.1 適用

- 本書は、共通部品の**呼出しインタフェース**、**権限マスタ**、**コード値マスタ**、**メッセージマスタ**、
  **エラーコード体系**、**アクセス制御標準**を定める。
- 各画面は本書の部品を**呼び出す**ものとし、**同等機能を画面側で再実装しない**。
- 提供形態は、共通 UI ライブラリ（TypeScript）および共通処理パッケージ（Python）の **v3.0** とする。
- 日時は **JST**、表示形式は **YYYY/MM/DD hh:mm:ss** とする。端末時刻は使用しない。

### 1.2 共通仕様値

| 項目 | 値 |
|---|---|
| 1 頁件数の候補 | **10／20／50／100 件** |
| 1 頁件数の既定値 | **20 件** |
| 検索の上限件数 | **500 件**（ちょうど 500 件は許容、超過は業務エラー） |
| セッション有効期限 | **最終操作から 30 分** |
| 頁番号 | **1 始まり** |
| オンライン稼働時間 | 平日 7:00–22:00（「共通前提条件書 v1.2」による） |

## 3. 各共通部品のインタフェース

### 3.1 共通ヘッダ `CommonHeader`

**呼出し**

```ts
CommonHeader.render(props: HeaderProps): void;
```

**引数（`HeaderProps`）**

| 引数 | 型 | 必須 | 内容 |
|---|---|---|---|
| `title` | string | ○ | 画面タイトル。画面ごとの固定値を渡す |
| `companyName` | string | ○ | ログイン利用者の会社名 |
| `departmentName` | string | ○ | ログイン利用者の部署名 |
| `userName` | string | ○ | ログイン利用者のユーザー名 |
| `serverTime` | string | ○ | サーバ時刻（`YYYY/MM/DD hh:mm:ss`、JST） |

**戻り**：なし（ヘッダ領域へ描画する）。

**遷移方法**：なし。ログアウトを伴う終了は、画面の「業務終了」から標準規約の遷移を呼ぶ。

**備考**

- 会社名・部署名・ユーザー名は**別々の表示項目**として描画する（連結しない）。
- 画面ごとにヘッダを実装してはならない。すべて本共通部品を呼び出す。
- システム日時は**サーバ時刻**を用いる。端末時刻を表示してはならない。

### 3.2 ページャ `Pager`

**呼出し**

```ts
Pager.render(props: PagerProps): PagerEvents;
```

**引数（`PagerProps`）**

| 引数 | 型 | 必須 | 内容 |

**戻り（`PagerEvents`）**

| 戻り | 型 | 内容 |
|---|---|---|
| `onFirst` | () => void | 先頭頁へ移動 |
| `onPrev` | () => void | 前頁へ移動 |

**表示要素**：先頭頁／前頁／頁番号／次頁／最終頁／総件数。**上部・下部の 2 か所**に同一仕様で描画する。

**備考**

- 頁番号は **1 始まり**。総件数 0 件のときは全操作を非活性とする。
- 検索の上限件数（500 件）を超える場合は、呼出元が業務エラー（`errorId=1002`）とし、ページャを描画しない。

## 4. 権限マスタ

### 4.1 権限コードの定義

| 権限コード | 名称 | 許可する操作 |
|---|---|---|
| **MKR01** | 参照権限 | 検索、一覧参照、マスタ画面の参照 |
| **MKR02** | 更新権限 | MKR01 の操作 ＋ 新規登録・複製・更新 |
| **MKR03** | 全操作権限 | MKR02 の操作 ＋ 削除・ダウンロード |

- 権限は**利用者 1 名につき 1 コード**を付与する（「共通前提条件書 v1.2」第 5 条）。
- **上位コードは下位コードの操作を含む**（MKR03 ⊃ MKR02 ⊃ MKR01）。
- 画面は**ログイン時に受領した権限コード**でボタンの活性を制御する。ただしこれは**誤操作防止の補助**であり、
  **最終的な可否は API 側で決める**。
- **API 側でも必ず権限を検証する。** 画面の活性制御は API の検証を代替しない。

### 4.2 エンドポイント別の必要権限（6 端点 × 3 権限）

| # | エンドポイント | 役割 | MKR01 | MKR02 | MKR03 |
|---|---|---|---|---|---|
| 1 | `POST /R60Maker/init` | 初期表示 | ○ | ○ | ○ |
| 2 | `POST /R60Maker/search` | 検索 | ○ | ○ | ○ |
| 3 | `POST /R60Maker/download` | CSV ダウンロード | **×** | **×** | ○ |
| 4 | `POST /R60Maker/initEdit` | マスタ画面の初期値 | ○ | ○ | ○ |
| 5 | `POST /R60Maker/delete` | 論理削除 | **×** | **×** | ○ |
| 6 | `POST /R60Maker/edit` | 新規・複製・更新 | **×** | ○ | ○ |

- ○＝実行可、**×＝権限不足**。権限不足のときは **`errorCode="1"`／`errorId="2004"`** で処理を中断する。
- 18 セルのうち**「不可」は 5 セル**（`download` の 2、`delete` の 2、`edit` の 1）。
- `/initEdit` は参照権限でも実行可とする（マスタ画面の参照に必要）。マスタ画面上の登録・削除の可否は
  `/edit`・`/delete` の権限検証で決める。
- 権限不足は**業務エラー**として扱い、画面遷移しない（メッセージ表示のみ）。

## 5. 被参照チェック部品

### 5.1 呼出し

```ts
ReferenceChecker.check(makerCd: string): number;
```

### 5.2 引数

| 引数 | 型 | 必須 | 内容 |
|---|---|---|---|
| `makerCd` | string | ○ | メーカーコード（**1〜5 文字**、半角英数字） |

### 5.3 戻り値

| 戻り | 型 | 内容 |
|---|---|---|
| 参照件数 | number | **0＝参照なし**、**1 以上＝参照あり** |

### 5.4 判定対象

- **購入品目別仕入先マスタ**
- **原材料仕入単価マスタ**

**削除済みの参照元は数えない**（削除区分＝1 のレコードは参照件数に含めない）。

### 5.5 想定外時の挙動

- 部品内部で判定不能な場合、`CommonComponentException` を送出する。
- 呼出元は **`errorCode="9"`／`errorId="9101"`** として**処理を中断**し、**システムエラー画面へ遷移**する。
- **参照件数を 0 として扱ってはならない**（「判定できなかった」と「参照なし」を混同しない）。

### 5.6 呼出しタイミング

- 削除処理の**排他の直前**に呼ぶ。
- 修正画面で**削除をオンにして登録する場合**も呼ぶ（削除処理と同一）。
- 削除をオンにしない修正では呼ばない。
- 部品は読み取りのみであり、何度呼んでも同じ結果となる（冪等）。

## 6. 緊急配信部品

### 6.1 呼出し

```ts
EmergencyDispatcher.dispatch(event: EmergencyEvent): string;
```

### 6.2 引数（`EmergencyEvent`）

| 引数 | 型 | 必須 | 内容 |
|---|---|---|---|
| `businessId` | string | ○ | 業務 ID（本画面は `"R60Maker"`） |
| `operation` | string | ○ | **`"1"`＝登録／`"2"`＝削除** |
| `makerCd` | string | ○ | メーカーコード |
| `makerNm` | string | ○ | メーカー日本語名 |
| `makerKanaNm` | string | ○ | メーカーカナ名 |
| `userId` | string | ○ | 操作した利用者 ID |
| `occurredAt` | string | ○ | 発生時刻（`YYYY/MM/DD hh:mm:ss`、JST） |

### 6.3 戻り値

| 戻り | 型 | 内容 |
|---|---|---|
| 受付 ID | string | 受付の証跡（例：`EQ-20251024-000001`）。**配信の成否ではない** |

### 6.4 挙動

- **非同期**で配信する。呼出しは受付 ID を返して**即時に復帰**する。
- **配信の成否・結果は呼出元へ返さない。**
- **失敗時は送信状態を 9（送信エラー）に更新する**（共通部品が更新する）。
- 受付自体に失敗した場合も、送信状態を **9** に更新する。**呼出元の業務トランザクションはロールバックしない**。
- **業務データのコミット確定後に起動する**。業務データの更新と同一トランザクションに含めない。
- 本画面は**再送を行わない**。同一受付 ID の再送抑止は配信基盤側で行う。

## 8. メッセージマスタ

### 8.1 メッセージ ID の採番規則

```
MSG-<種別>-<3 桁連番>
```

- 種別は **E**（エラー）／**W**（警告）／**I**（情報）／**C**（確認）の 4 種。
- 連番は**種別ごとに 001 から**払い出す。**欠番の再利用は禁止**。
- メッセージは共通メッセージマスタで一元管理し、**画面側で文面を直書きしない**。
- 応答の `messages[]` は **`{ "code", "kind", "text" }`** の配列とする。`kind` の値域は `E`／`W`／`I`／`C`。

### 8.2 本画面が使用する代表メッセージ

| メッセージ ID | 種別 | 文面 | 用途 |
|---|---|---|---|
| **MSG-E-001** | E | 該当するデータがありません。 | 検索結果 0 件 |
| **MSG-E-002** | E | 検索結果が上限件数（500 件）を超えました。条件を絞り込んでください。 | 上限超過 |
| **MSG-E-003** | E | メーカーコードは既に登録されています。 | キー重複 |
| **MSG-E-004** | E | 他のマスタから参照されているため削除できません。 | 被参照 |
| **MSG-E-005** | E | 他の利用者が先に更新しました。最新の内容を確認してください。 | 排他 |
| **MSG-E-006** | E | 操作する権限がありません。 | 権限不足 |
| **MSG-E-007** | E | {0}は必須です。 | 必須チェック違反 |
| **MSG-E-008** | E | {0}の形式が正しくありません。 | 桁・文字種チェック違反 |
| **MSG-I-001** | I | 登録が完了しました。 | 登録完了 |
| **MSG-I-002** | I | 削除が完了しました。 | 削除完了 |
| **MSG-I-003** | I | 変更はありません。 | 変更なし |
| **MSG-C-001** | C | 登録してよろしいですか？ | 登録確認 |
| **MSG-C-002** | C | 削除してよろしいですか？ | 削除確認 |
| **MSG-C-003** | C | 変更内容は破棄されます。一覧へ戻ってよろしいですか？ | 戻る確認 |
| **MSG-C-004** | C | 業務を終了してよろしいですか？ | 業務終了確認 |

- `{0}` は項目名称に置換する（例：`MSG-E-007` の `{0}` →「メーカーコード」）。

## 9. エラーコード体系

### 9.1 応答形式

```json
{
  "errorCode": "0",
  "errorId": "0000",
  "messages": [
    { "code": "MSG-I-001", "kind": "I", "text": "登録が完了しました。" }
  ]
}
```

| 項目 | 型 | 内容 |
|---|---|---|
| `errorCode` | string（1 桁） | **`0`＝正常／`1`＝業務エラー／`9`＝システムエラー** |
| `errorId` | string（**4 桁**） | 個別事象の識別子。正常時は **`0000`** |
| `messages` | array | `{code, kind, text}` の配列。複数件を返せる |

- HTTP ステータスは**すべて 200** とし、エラーの判定は**本文の `errorCode` を正**とする
  （プロキシ・ゲートウェイのエラー画面に置き換えられないようにするため）。
- `errorCode` に **`2` は使用しない**。`errorCode` は 0／1／9 の 3 値のみ。

### 9.2 errorId 体系

| errorId 帯 | 用途 |
|---|---|
| `0000` | 正常 |
| `1001`–`1999` | 検索・一覧 |
| `2001`–`2999` | 登録・更新・削除・権限 |
| `9001`–`9999` | 共通・システム |

### 9.3 本画面が使用する代表 errorId

| errorId | errorCode | 事象 | 画面の動作 |
|---|---|---|---|
| `0000` | 0 | 正常 | なし |
| `1001` | 1 | 検索結果 0 件 | メッセージ表示、明細を表示しない |
| `1002` | 1 | 検索上限（500 件）超過 | メッセージ表示、明細・CSV を出力しない |
| `2001` | 1 | キー重複 | メーカーコードを強調表示 |
| `2002` | 1 | 被参照あり | メッセージ表示、削除しない |
| `2003` | 1 | 排他エラー | メッセージのみ表示（項目強調なし） |
| `2004` | 1 | 権限不足 | メッセージ表示、処理を中断 |
| `2005` | 1 | サーバ側入力チェック違反 | メッセージ表示、処理を中断 |
| `9001` | 9 | セッション無効 | **セッションエラー画面へ置換** |
| `9002` | 9 | オンライン利用不可 | **オンライン制御エラー画面へ置換** |
| `9101` | 9 | 被参照チェックの想定外 | **システムエラー画面へ置換** |
| `9999` | 9 | DB エラー・想定外の例外 | **システムエラー画面へ置換** |

## 10. アクセス制御標準

### 10.1 API 前処理の順序

すべての API は、業務処理の前に**次の順序**で前処理を行う。**1 つでも失敗したら後続を実行しない。**

| 順 | 前処理 | 内容 | 失敗時の応答 |
|---|---|---|---|
| 1 | **セッション** | セッション情報の存在と有効期限（最終操作から **30 分**）を検証する | `errorCode="9"`／`errorId="9001"` |
| 2 | **オンライン可否** | オンライン利用が許可されているか（稼働時間・計画停止）を検証する | `errorCode="9"`／`errorId="9002"` |
| 3 | **権限** | §4.2 のエンドポイント別必要権限を検証する | `errorCode="1"`／`errorId="2004"` |
| 4 | **入力チェック** | 単項目・桁・文字種を画面と同一条件で検証する | `errorCode="1"`／`errorId="2005"` |

### 10.2 画面側の扱い

| 応答 | 画面の動作 |
|---|---|
| `errorCode="0"` | 正常処理を継続する |
| `errorCode="1"` | メッセージを表示し、**処理を中断**する。画面遷移しない |
| `errorCode="9"`／`errorId="9001"` | **セッションエラー画面**へ置換する |
| `errorCode="9"`／`errorId="9002"` | **オンライン制御エラー画面**へ置換する |
| `errorCode="9"`／その他 | **システムエラー画面**へ置換する |

- **権限不足（`2004`）は業務エラー**として扱い、画面遷移しない。
- 画面のボタン活性制御は**補助**であり、API の権限検証を省略してはならない。
