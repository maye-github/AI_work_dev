# kb-query — 会話から知識庫を引く

> **目的**：人にコマンドを覚えさせない。人が言うのは「〜を調べて」だけでよい。
> 正本は `tools/kb-platform/知识库使用手顺.md`（操作手順）と `kb-policy.md`（規則）。

## 0. このスキルの立ち位置

知識庫の**読み取り**を会話で行うための手順である。
**書き込み（昇格・移送・結案）は人が明示的に承認したときだけ**実行する（紅線③）。

コマンドは**すべてリポジトリルート**で実行する（`-m tools.xxx` は `tools` をパッケージとして
import するため、`tools/` の中に居ると `No module named 'tools'` で落ちる）。

---

## 1. 最初に必ずやること：操作者を確定する

読権限は `--as <人>` で決まる。**付け忘れると会社級しか返らない**（既定は拒否）。

```bash
py -3 -m tools.kb_local whoami
```

| 結果 | 対応 |
|---|---|
| 名前が返る | その名前を `--as` に使う |
| `（未設定）` | **人に 1 回だけ聞く**：「`owners.yaml` に登録されている方のお名前は？」 |

### ★ 名乗りは**会話で完結させる**（人にコマンドを打たせない）

人が「我是 Li」「叫我 Li」「记住我是谁」と言ったら、**こちらで `whoami --set` を実行して保存する**。
「ターミナルで `whoami --set` を打ってください」と返してはならない——**このスキルは
「コマンドを覚えさせない」ためにある**。

1. 名乗られたら `owners.yaml` に居るか確かめる（`kb_acl show` で一覧が出る）
2. 居れば `py -3 -m tools.kb_local whoami --set <名前>` を実行
3. 居なければ「その名前は登録にありません。誰の名前で入りますか？」と**聞き返す**
   （**勝手に `--all` で回避しない**）
4. 保存したら「以後、名乗らなくて大丈夫です」と 1 行返す

## 1.5 質問 → 何をするか（★ここが本体）

**人が打つのは「質問」だけである。コマンドはこちらで組む。**
下は例であって、言い回しは自由。**意図が読めれば同じ動作を選ぶ。**

| 人が言う | こちらが実行する |
|---|---|
| 「〜を調べて」「以前どうしてた？」 | `kb_local search`（`--as` は whoami から補う） |
| 「〜の先例ある？」 | `kb_local search` → 先例（`TPL-*`/`PAT-*`/案件事実）を優先して返す |
| **「この知識、誰が使った？」「どの成果物が引用してる？」** | `kb_refs cited <doc_id>` |
| **「使われてない知識は？」「一度も引かれてないものは？」** | `kb_refs cited --zero` |
| 「知識庫いまどうなってる？」 | `kb_local stats` ＋ `kb_refs cited`（0 回が多い点も添える） |
| 「昇格できそうなのは？」 | `kb_promote candidates`（ガイド §2.1 の五類で分類して返す） |
| 「これ昇格できる？」 | `kb_promote check <file>` |
| 「sources の資料を入れて」 | `kb_local import --scan`（先に `--dry-run` を見せる） |
| 「索引は最新？」「入れ忘れてない？」 | `kb_local freshness` |
| 「これ我有権改める？」 | `kb_acl check --by <whoami> --from-git` |
| 「誰がこれを変えられる？」 | `kb_acl show` |
| 「この資料、対外に出せる？」 | `kb_local external-check <file>` |
| 「節点N は何を引くべき？」 | `kb_refs show --node N` |

**返すときの原則**：数字と出典を添える。「0 回」も隠さない——**使われていない事実こそ判断材料**。

---

## 2. どこを引くかを決める

| 人の言い方 | 引く範囲 |
|---|---|
| 案件名・画面名を出した（「R60 の排他は？」） | `--project <P-ID>` を付ける |
| 「一般的には」「規約は」 | `--scope company` を付ける（またはそのまま） |
| 何も言わない | まず会社級で引き、足りなければ案件を聞く |

案件 ID が分からないときは `py -3 -m tools.kb_local stats` で一覧を見る。

---

## 3. 引く

```bash
# 基本
py -3 -m tools.kb_local search "<問い>" --as <人> [--project <P-ID>] --top-k 5

# モジュールが分かっているとき（同じ語幹の別モジュールを避ける）
py -3 -m tools.kb_local search "<問い>" --as <人> --project <P-ID> --module <R60XXX>

# 先例の候補を出す（節点産出に添える用）
py -3 -m tools.kb_refs suggest --project <P-ID> --as <人> --query "<主題>"
```

### 検索語の作り方

- **名詞を 2〜3 個**並べる（「排他 更新日時」「画面遷移 セッション」）
- 疑問文をそのまま入れない（「〜はどうなっていますか」は効かない）
- 0 件なら語を入れ替える。**「庫に無い」と決めるのは 2 回外したあと**

---

## 4. 結果の返し方

**そのまま貼らない。** 次を満たす形に整える。

1. **出典を必ず添える**：`[doc_id] タイトル § 節`
2. **会社級か案件級かを書く**
3. 要点は 2〜3 行。原文が要るときは「全文は `<path>`」とパスを示す
4. 引いた先例が**規則の摘要（`STD-*`）だけ**だった場合は、その旨を添える
   （規則は `rules/` が常時読み込むので、先例としては弱い）

返し方の例：

```
案件知識から2件（P-R60-001）:

1. [r60-001-modules-r60sesmodel-03-logic] R60SesModel — 業務ロジック § logics
   排他は KSN_DAT と REV_NO の組で判定している。

2. [r60-001-05-database] 05 データベース定義 § 4.2
   全テーブル共通の監査列として KSN_DAT / REV_NO を持つ。

※ 2 は「推測」と明記された節です。確定値は詳細設計を確認してください。
```

**原文に「推測」「未確定」と書いてあれば、そのまま伝える。** 都合よく省かない。

## 5. 読むだけの操作（いつでも実行してよい）

| 目的 | コマンド |
|---|---|
| 何が入っているか | `py -3 -m tools.kb_local stats` |
| 形式の検査 | `py -3 -m tools.kb_local lint` |
| 出処の点検 | `py -3 -m tools.kb_local extra report` |
| 誰が何をできるか | `py -3 -m tools.kb_acl show` |
| 昇格候補 | `py -3 -m tools.kb_promote candidates --project <P-ID> --types template,glossary,standard` |
| 匿名化体检 | `py -3 -m tools.kb_promote check <file>` |
| 改写下書き | `py -3 -m tools.kb_promote draft <file>` |
| 移送の予演 | `py -3 -m tools.kb_promote plan ...` |
| 逆引き（この知識を誰が使ったか） | `py -3 -m tools.kb_refs cited <doc_id>` |
| 一度も使われていない知識 | `py -3 -m tools.kb_refs cited --zero` |
| 成果物の先例検査（全体） | `py -3 -m tools.kb_refs scan` |
| 取り込みの予演 | `py -3 -m tools.kb_local import --scan --by <人> --dry-run` |

## 6. 書く操作（**人が明示的に承認したときだけ**）

| 操作 | 条件 |
|---|---|
| `apply`（移送） | 人が「移送して」と言い、**`--by` に実名**を入れる。予演（`plan`）を先に見せる |
| `close`（結案） | 同上。`CLOSED.md` は人の署名欄を空けたまま出す |
| `init-glossary` | 同上。案件の PM でなければ通らない |
| `ingest`（索引更新） | ファイルを変えたあとなら実行してよい（読み手に影響するが破壊的でない） |

**やってはいけないこと**：

- `--by` に AI の名前や推測の名前を入れる（承認が無効になる）
- 人の承認前に `apply` / `close` を実行する
- 移送先や `doc_id` を勝手に決めて実行する（`plan` を見せて確認を取る）

---

### 6.1 資料（Excel / Word / PDF）の取り込み

人が「sources の資料を知識庫に入れて」「この Excel を取り込んで」と言ったときの手順。

```bash
# 1. 予演（何がどう変換されるか）
py -3 -m tools.kb_local import --scan --by <人> [--project <P>] --dry-run

# 2. 人が「入れて」と言ったら実行
py -3 -m tools.kb_local import --scan --by <人> [--project <P>]
```

**必ず守ること**

| 手順 | なぜ |
|---|---|
| 先に `--dry-run` で予演を見せる | 「何件・どのファイルが」変換されるかを先に知らせる |
| 抽出報告（sheet 数・行数・**結合セル数**・字数・警告）を**そのまま**渡す | 人はその数字で「原本と合っているか」を判断する |
| **`status: draft` のまま止める** | 機械が抽出したものを、人が見る前に検索させない |
| `open` への変更は**人が明示したときだけ**代行し、**何件変えたかを報告**する | 承認は人。代行した事実は残す |

> **`--by` は案件の PM の実名**。PM でなければコマンドが拒否する（`kb_acl`）。
> 「誰の名前で入れるの？」と聞かれても、**推測で埋めない**。

---

## 7. 禁止事項

1. **`--all` で読権限を回避しない。** 使うのは人が「全部見せて」と言ったときだけ。
2. **規則の摘要を「先例」として提示しない。** `STD-*`（`company/standards/`）のうち
   `canonical: true` でないものは規則の要約であり、先例ではない。
   先例は案件の事実・`TPL-*`・`PAT-*`・**`canonical: true` の `STD-*`**（方法の正本。`kb-policy.md` §2.4）。
3. **0 件を「無い」と断定しない。** 語を変えてもう一度引く。それでも 0 件なら
   「この語では見つからない」と言う（「存在しない」とは言わない）。
4. **推測で補わない。** 検索結果に無いことを、それらしく書かない。
5. **`tools/` の中でコマンドを実行しない。** 必ずリポジトリルートから。

---

## 8. うまくいかないとき

| 症状 | 対処 |
|---|---|
| `No module named 'tools'` | リポジトリルートへ移動してから実行 |
| 会社級しか出ない | `whoami` を確認し `--as` を付ける |
| `--as` の人がどの案件にも居ない | `owners.yaml` の `members` に追加してもらう |
| 0 件 | 語を変える → `stats` で入っているか確認 → `ingest --prune` を促す |
| 古い内容が出る | ファイルを変えたあと `ingest` を忘れている |
