# 機密紅線規則 - Level 3（禁止外投・社外秘）

## 機密レベル区分

| Level | 定義 | 対外扱い |
|-------|------|----------|
| L1 | 公開可 | 外部OK |
| L2 | 要脱敏 | 占位化の上OK |
| L3 | **禁止外投** | 社内限定・masking 必須 |

> **運用原則**: L3 の値は、外部 LLM・外部 SaaS・公開リポジトリへ一切出さない。
> やむを得ず外部へ渡す場合は `tools/masking/mask_demo.py` で **脱敏占位** してから渡す。
> 本ファイルは L3 キーワードの「定義場所」であるため、`tools/trace_check.py` gate6 の
> 走査対象から除外している（他のファイルはすべて走査対象）。

---

## L3 禁止外投 13 条

以下 13 項目はすべて **Level: 禁止外投**。各項に **脱敏占位** の規則を必ず併記する。

### 1. Oracle 接続文字列
- **Level: 禁止外投**
- 原文想定: 接続ユーザ / ホスト / ポート / SID の組（社内専用網）
- Masked: `TBL_1/COL_1@PWD_1:PORT_1/SID_1`
- **脱敏占位ルール**: 接続ユーザ→`TBL_1`、パスワード→`PWD_1`、ホスト→`IP_1`、SID→`SID_1` に置換する。

### 2. Auth0 設定
- **Level: 禁止外投**
- 原文想定: Domain / Audience（社内テナント固有値）
- Masked: Domain `DOM_1` / Audience `https://AUD_1`
- **脱敏占位ルール**: テナントドメイン→`DOM_1`、Audience URL→`https://AUD_1` に置換する。

### 3. AWS S3 Bucket
- **Level: 禁止外投**
- 原文想定: 成果物出力用バケット名（環境名・案件番号を含む）
- Masked: `BUCKET_1`
- **脱敏占位ルール**: バケット名全体を `BUCKET_1` に置換し、環境名・案件番号を残さない。

### 4. AWS Profile
- **Level: 禁止外投**
- 原文想定: 命名規約つき AWS プロファイル名
- Masked: `PROFILE_1`
- **脱敏占位ルール**: プロファイル名全体を `PROFILE_1` に置換する。

### 5. 社員コード暗号化鍵（当日鍵）
- **Level: 禁止外投**
- 原文想定: 当日 Key（yyyymmdd 形式）とマスタパス。方式は案件設計に従う（R60 は AES-256-ECB ではない）
- Masked: `KEY_1`
- **脱敏占位ルール**: 鍵・マスタパスを `KEY_1` に置換し、日付そのものも残さない。

### 6. .env 内パスワード・鍵全般
- **Level: 禁止外投**
- 原文想定: `DB_PASSWORD` / `API_SECRET` / `TOKEN_SALT` 等の値
- Masked: `PWD_1`
- **脱敏占位ルール**: 値をすべて `PWD_1` に置換する。キー名（変数名）は残してよい。

### 7. 内部セグメント IP アドレス
- **Level: 禁止外投**
- 原文想定: 社内専用網セグメント（RFC1918 のうち案件固有の割当範囲）
- Masked: `IP_1`
- **脱敏占位ルール**: アドレス全体を `IP_1`（セグメント表記なら `IP_1/16`）に置換する。

### 8. 社内メールアドレス
- **Level: 禁止外投**
- 原文想定: `name.surname@<社内ドメイン>` 形式の実在アドレス
- Masked: `MAIL_1`
- **脱敏占位ルール**: アドレス全体を `MAIL_1` に置換し、ローカル部・ドメイン部とも残さない。

### 9. DB オブジェクト名（R60_*_FNC 系）
- **Level: 禁止外投**
- 原文想定: 業務固有のストアド・ファンクション名
- Masked: `TBL_1_FNC`
- **脱敏占位ルール**: オブジェクト名を `TBL_1_FNC` に置換する。汎用名（`R60_*` の接頭辞のみ等）は残してよい。

### 10. 32 モジュール業務データ実値
- **Level: 禁止外投**
- 原文想定: 部門コード / 品番 / 金額 / 受注番号などの実データ
- Masked: `COL_1 = VAL_1`
- **脱敏占位ルール**: 列名→`COL_1`、値→`VAL_1` に置換する。型・桁数は残してよい。

### 11. 緊急配信トリガー条件
- **Level: 禁止外投**
- 原文想定: 「どの業務 ID・ステータス遷移が緊急配信を発火させるか」という条件式
- Masked: `IF TRG_1 THEN SET X = '9'`
- **脱敏占位ルール**: 条件式の業務 ID・判定値を `TRG_1` に置換する。
  なおステータス定数そのものは業務値であり、運用 Runbook の切戻し手順で言及するのは正当。
  したがって gate6 は「条件式として書かれた形」のみを検出する。

### 12. 復号ファンクション実引数
- **Level: 禁止外投**
- 原文想定: 復号ファンクション呼出しに渡す実引数（社員コード・パスワード・当日鍵）
- Masked: `TBL_1_FNC(COL_1, PWD_1, KEY_1)`
- **脱敏占位ルール**: 実引数を `COL_1` / `PWD_1` / `KEY_1` に置換する。

### 13. 実在社員コード・氏名
- **Level: 禁止外投**
- 原文想定: 実在の社員番号・氏名
- Masked: `EMP_1 = NAME_1`
- **脱敏占位ルール**: 社員番号→`EMP_1`、氏名→`NAME_1` に置換する。個人が特定できる組み合わせを残さない。

## 補足: 顧客名の扱い（L3 ではないが L2 相当・出口で脱敏）

上記 13 条に**顧客名は含まれない**。本骨架は社内資産であるため、案件を特定する顧客名
（例: 朝日ビール）を**内部機読源（`docs/**`・`.claude/**`・`CLAUDE.md`）に記載することは可**とする。

- **内部**: 記載可（可読性のため。抽象化すると R60 実例が読めなくなる）
- **対外**: 日方へ提出する媒体（顧客確認依頼書・日文正式 Excel・報告書等）へ出す場合は
  **必ず `tools/masking/mask_demo.py` を通し、顧客名を占位へ置換してから出す**（红线⑦）。
- **判断基準**: 「これは社外に出るか？」。社外に出るなら脱敏必須、社内に留まるなら可。
- **禁止**: 顧客名と実データ値・実 IP・接続情報を**同一行・同一表で併記**すること
  （組み合わせで案件が特定されるため）。
