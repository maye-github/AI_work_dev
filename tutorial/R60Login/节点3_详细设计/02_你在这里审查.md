> ③ 你自己对业务与工程边界的判断。**

## 一、追溯（链条断一处，后面全白做）

- [ ] **F-201 之下 L-201〜L-208 共 8 条，分割粒度你认不认**。
  - 为什么必须人看：粒度是判断题，不是格式题。切太细会把一个事务拆成两个（Session 只建了一半就被测），
    切太粗会让制造阶段开始「猜」。AI 会按「看起来自然」切，但那不等于对。
- [ ] **I-301〜I-320 共 20 项，每一项都落到了物理名**（上流 §4 的 12 项 + §7 的 8 项）。
  - 为什么必须人看：上流分两处定义（§4 表格 12 项、§7 接口 8 项），编号连不连得上要人一个个数。
    AI 容易只处理表格里的那一批。
- [ ] **E-201〜E-210 共 10 件，§6.1（分岐）和 §6.2（文面）都出现了，且每件都有迁移目标**。
  - 为什么必须人看：文面与分岐是两张表，AI 常常补齐一张、漏掉另一张。
- [ ] **★ 上流 05 的非 Q 栏也逐条对过**：限定句（「〜のみ」「〜を除く」）、内部值的符号系（画面 `Y`/`N` 与
    内部 `1`/`0`）、形状（URL 的路径固定部分与区隔）、否定与例外（「〜しない」）。
  - 为什么必须人看：Q 栏是未确定事项的清单，不是内容的清单。**上流表里没进 Q 栏的行，恰恰最容易掉**
    （规则 02 §9 的实测：R60Login 节点2 掉了 3 件，全在非 Q 栏）。

## 二、业务正确性（AI 最容易「看起来对」的地方）

- [ ] **6 个步骤的固定顺序**：①稼働チェック → ②復号 → ③社員検証 → ④社員情報取得 → ⑤Session 生成 →
  ⑥遷移先解決。设计书 §2.3 与上流 §6 一致。
  - 为什么必须人看：顺序一换就会出现「稼働停止中仍然解密」「先发 Session 再验身份」这类洞。
    AI 会照抄上流的顺序，但它**不会替你检查抄对没有**。
- [ ] **SQL-1〜SQL-6 用到的列，全部在本节点 §3 定义的 5 张表里**，没有表外的列、没有自造的条件。
  - 为什么必须人看：列名与表构造是**本节点自己定的**（Q-227 的命名规约）。自己定的东西自己核，
    机械比对只能查「有没有定义」，查不出「定义得对不对」。
- [ ] **稼働判定（L-201）是共通前处理**，/init・/login・/generateUrl 三个端点都在最前面走它。
  - 为什么必须人看：漏一个端点，就等于那条路绕开了稼働停止。这是安全洞，不是笔误。
- [ ] **加密・复号（L-206）按上流 §10.3 的算式**（桁转换＋当日日付加算），**不是 AES-256-ECB**。
  - 为什么必须人看：算式是客户既有规约的产物，AI 训练语料里「加密」几乎都是 AES。
    设计书写成 AES，实现就会照做，且测试很难发现（自加密自解密照样通过）。
- [ ] **E-204 的「连续 3 回」按 Q-230 裁定**：同一客户端内计数、成功即归零、不设时间窗。
  - 为什么必须人看：计数的单位（人／会话／系统全体）上流没写，是我们定的。定错了就是全站互踢。
- [ ] **E-203 的文面不泄露「该员工是否存在」**，与上流 §9.2 的文面一致。
  - 为什么必须人看：这是安全问题。AI 默认会写「該当社員が存在しません」——那就泄露了。

## 三、红线合规（碰了就是废品）

- [ ] **没有在本节点把技术栈定下来**（紅線④）。
  - 为什么必须人看：greenfield 的栈在工程04 由我方提案、人承认后确定。本节点写死框架名，
    等于在承认之前就定了。AI 极易顺手写「FastAPI で実装する」。
- [ ] **没有野号**：只用 L-201〜L-208 / D-201〜D-205 / I-301〜I-320 / E-201〜E-210。
  - 为什么必须人看：教学号段不进 `ids.yml`，门禁**不会**替你拦（実案件则会被 gate1 拦）。
- [ ] **SQL 的值全部是 `:bind`**，没有把实值写进 SQL 字符串。
  - 为什么必须人看：`trace_check` 不查这个；写死了值，测试和本番就会共用同一份数据。
- [ ] **本画面只有 read**：没有把 write、排他（`ksn_dat` 等）带进设计。
  - 为什么必须人看：上流定的是「只读」，AI 会按「登录＝写 Session」的常识补出写操作，
    那就超出了基本设计的范围（詳細設計不得超越基本設計）。
- [ ] **没有真实敏感值**（连接信息、键、真实员工代码・姓名、真实 IP）。
  - 注意：**密钥的实值绝对不写**。写得出算法，写不出键。
- [ ] **没有读过冻结范围（历史案件素材）里的任何文件**（greenfield 不参照旧系统）。
  - 为什么必须人看：读了旧实现就会「写经」，训练就变成抄写，后面所有对比数据都不算数。

## 五、未确定事项的处置 ★（本节点的核心）

  I-317 的供给来源、「连续 3 回」的计数单位。

- [ ] **Q-231〜Q-238 共 8 件，逐件定 A／B／C**。

  - **B＝我方提案・顾客承认**（运用的决定、使用者看得见的行为、对外的约定）

  - 参考气味试验：A ≦ 1/4、C ≧ 1/3。
