- **根拠**：05 §2.7 算式 #4（整数加算の対象が日付そのもの）／05 §8.3（「当日鍵の実値・格納場所を本書に書かない」は
  **書くべき実値が無い**ことの裏返し）／05 §2.7・§8.3（引数注入・JST・当日内のみ）。
- **是正の内容**：05 §9「工程04 へ送る事項 3（当日鍵の取得方式と格納先）」は**前提が空振りしている**。
  工程04 が決めるのは **DB 接続情報の取得方式**である。**上流は書き換えていない**（設計を直すなら変更環）。

### 6.4 HO-04 画面の「保持領域」の実体

| 項目 | 結論 |
|---|---|
| 保持の実体 | `kgnKbn`（権限区分）を**同一オリジンの localStorage** に 1 キーで保持（キー名 `r60login.kgnKbn`、値 `Y`／`N`） |
| 理由 | 遷移は新規ウィンドウ／タブであり、localStorage は**同一オリジンのウィンドウ間で共有される**（手動で開いたタブでも共有）。sessionStorage は **opener 経由の `window.open` でしか複製されない**（一般論 E4） |
| 残留対策 | ログイン成立時に**必ず上書き**し、**画面終了時に明示的に削除する**（前回の権限区分を次回起動へ持ち越さない） |
| URL に載せない | `kgnKbn` は URL に載せない（05 §2.5 ステップ 4） |
| 前提 | **SCR-201（ログイン）と遷移先 SCR-202 が同一オリジンであること**（§7 前提 1） |

- **根拠**：05 §2.5 ステップ 4（`kgnKbn` は保持領域、Session 識別子は Cookie、`stfKbn` はクエリ）／05 §4.1 I-307／
  ブラウザ仕様（一般論 E4）。保持の実体と残留対策は**本節点の決定（C）**である。

## 7. 前提条件

本節点の結論が成立するための前提である。**各前提が成立しない場合の帰結を同じ行に書く**（成立しないまま実装しない）。
前提の当否は **`n04.yml` の OQ-01／OQ-02／OQ-05** の答えで確定する。**AI が倒推した仮想答案は事実として扱わない。**

| # | 前提 | 成立しない場合の帰結 |
|---|---|---|
| 1 | **共通基盤の 4 画面（メニューヘッダ・Session エラー画面・オンライン利用エラー画面・システムエラー画面）が同一オリジンであること**（05 §1.2） | 別オリジンなら、Cookie の属性（SameSite／Domain）と §6.4 の保持領域の方式が変わる。**設計変更（CR）**として扱い、§6.4 は無効になる |
| 2 | **Session 破棄要求の相手が存在すること**（顧客の共通基盤の Session 管理機能。05 §2.9 ステップ 3・裁定 Q-232） | 相手が存在しない場合、L-208 ステップ 3 を「**自分の Session を破棄する**」に読み替える。裁定 Q-232 の前提に関わるため**設計変更（CR）**である |
| 3 | **Session をサーバ側に保持できること**（05 §8.2） | 保持先は冗長化構成に依存する。多重インスタンスで共有できず**外部ストアが必要なら構成変更（CR）**となる（05 §8.2 の水準値は変えない） |
| 4 | **§6.1 のルート規約（画面 `/R60/{gmnId}`／API `/R60Login/`）が承認されること** | `05 §2.5` は「工程04 のルーティング規約で最終確定」としており、その最終確定が本記録である。承認されない場合、画面ルートは未確定のまま実装へ渡せない |

- 前提 1〜3 は **OQ-01／OQ-02／OQ-05** に対応する。**OQ-03（ログ基盤の提供元）／OQ-04（シークレット管理基盤）**は
  §6.2・§6.3 の方式を変えない（送出先と格納先の種別が決まるだけである）。
