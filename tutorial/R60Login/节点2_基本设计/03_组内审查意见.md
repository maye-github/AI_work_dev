### 意见-01　【SE】　稼働停止時の振る舞いが「通用エラー」になっている

- **指摘**：AI 把「稼働中かどうかのチェックに失敗（E-201）」写成了「显示通用错误并留在登录画面」。
- **希望怎么改**：节点1 の承認版 **BR-201-01** は「稼働していない場合は**ログインさせず、明確なメッセージを提示**する」と要求している。
  「明確な」の具体化は**我方の設計**なので、当方が決めてよい（C 類）。E-201 の処理を
  「稼働停止であることが利用者に分かる専用の提示を行い、ログイン画面には留めない」と書き、
  **その根拠として BR-201-01 を引く**こと。

### 意见-02　【SE】　Q 番号の扱いと、暫定値の置き方を直す

- **指摘**：两个问题。
  ① 本文第 8 节的未决项里，**出现了与节点1 同号但含义不同的 Q**（节点1 の `Q-202` は「ログイン失敗ロック」、
  本節点で同じ `Q-202` を使うと別物に見える）。
  ② Session 超時（节点1 `Q-201`）について、本文は「暫定 30 分で先行」と書いている。**これが誤り。**
  节点1 の承認版で `Q-201` は **A 類（顧客が決める）** のままであり、しかも节点1 の RV-201-02 が
  「顧客が決める事項を当方が先に埋めた」ことを**すでに指摘・是正済み**である。本節点で同じ違反を繰り返している。
- **希望怎么改**：
  - ロック回数は**节点1 の結論（`Q-202`＝当方提案「連続 3 回」・顧客承認待ち）を引用するだけ**にして、本節点で再定義しない。
  - Session 超時は**暫定値を置かない**（`default_proposal: null`）。本節点の未決として **`Q-221`** で継続追跡し、
    「节点1 `Q-201` の回答を待つ」と明記する。
  - **本節点の新規未決は `Q-220` 以降**の番号にし、节点1 の `Q-201`〜`Q-212` と衝突させない。
    （持ち越した未決は同番号のまま追跡する。）

### 意见-03　【PG】　工程02 の時点で技術スタックを確定させている（紅線④）

- **指摘**：本文の约束（constraints）に「Vue3 + FastAPI + Oracle で実装する」と書き切っている。
  しかし本案は greenfield であり、**採用スタックは工程04（框架・環境構築）で当方が提案し、人が承認する**（紅線④）。
  工程02 の時点で確定させるのは、**人が承認する前に確定させたこと**になる。
  节点1 の `Q-212`（要求書の技術言及は制約か参考情報か）も**未回答**なので、なおさら確定できない。
- **希望怎么改**：约束からスタックの断定を**削除**し、「スタックは工程04 で決定する（紅線④）」に置き換える。
  本節点では**要求の範囲だけ**を設計する。

### 意见-04　【PG】　エラー処理に抜けがある（復号失敗・DB 接続失敗）

- **指摘**：两个缺口。
  ① `E-202`（復号失敗）は「回登录画面」としか書かれておらず、**復号の入参が何か・異常時に何をするか**が無い。
  ② 手順①の稼働チェックは DB を使うが、**DB 接続そのものに失敗した場合**の扱いが無い（`E-206` は Session 生成失敗しか書いていない）。
- **希望怎么改**：
  - `E-202`：入参は **`I-301 stfCd`**（画面側で暗号化された社員コード）であることを明記し、異常時は
    E-202 として扱いログイン画面へ戻す。ログ出力時は**敏感値を占位化**する。
  - `E-206`：DB 接続取得失敗もシステムエラーとして扱い、**底層の例外を利用者に見せず**、運用ログへ記録する。
  - **注意**：復号の実施主体（画面側で暗号化し API 側で復号する）は、节点1 `Q-206` の**当方提案であり顧客承認待ち**である。
    **承認済みの事実として書かない**こと（「当方提案・承認待ち」と注記する）。

### 意见-05　【QA】　错误一览的文面与「不泄露存在性」不一致

- **指摘**：`E-203` の備考には「存在を推測させない」と書いてあるのに、**エラーの見出しが「社員が存在しません」**になっており、自相矛盾している。
  文書自体を読めば存在／不存在が読み取れてしまう。
- **希望怎么改**：`E-203` の**文面を「社員コードが正しくありません」に統一**し、見出しも中性的な表現
  （例「社員検証エラー」）に変える。节点1 **BR-201-08** が要求している内容であることを根拠として引く。

### 意见-06　【SE】　画面 ID 需要说明「本机能不实现 SCR-202」

- **指摘**：SCR-202 写在「画面一览」里，容易被误解为本机能的制造范围。
- **希望怎么改**：在 SCR-202 行明确标注**「本機能は遷移先 URL を決定して返すところまでが責務。画面本体は他機能に属し、本節点の製造対象外」**、
  并在功能概要里点明本机能的责任边界到「决定并返回遷移先 URL」为止。
