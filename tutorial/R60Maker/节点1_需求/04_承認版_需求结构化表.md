## 1. 目的

調達・生産系共通マスタのうち、**メーカーマスタ**の維持管理画面を新規に構築する。
メーカーマスタは**購入品目別仕入先マスタ**および**原材料仕入単価マスタ**から参照される基礎データであり、
登録・変更・削除の際に**参照関係を壊さない**ことが求められる。

## 2. 対象範囲

### 2.1 対象

- **検索画面**・**マスタ画面**の 2 画面
- 両画面が利用する **6 つの API 端点**

### 2.2 対象外（Non-Goals）

| # | 対象外 |
|---|---|
| 1 | 購入品目別仕入先マスタ・原材料仕入単価マスタの各画面そのもの（本画面は参照の有無を確認するのみ） |
| 2 | 緊急配信の配信処理そのもの（共通部品を呼び出すのみ） |
| 3 | メーカー情報の一括取り込み（アップロード） |
| 4 | 登録内容の**確定操作**（確定は夜間の共通マスタ確定処理が行う。本画面に確定操作は無い） |
| 5 | 緊急配信の**再送**（本画面の機能外） |

## 3. 画面の役割

| 項目 | 結論 |
|---|---|
| 画面概要 | メーカー情報のメンテナンス（参照・登録・更新・削除・ダウンロード） |
| 利用対象者 | **利用権限保持者のみ**。権限コード（参照のみ／参照＋登録＋更新／全操作）で操作可否を決める |
| 使用頻度 | 月次・随時 |
| 画面区分 | 参照・登録・更新・削除・ダウンロード |

**権限の適用範囲**：利用権限は**画面の操作可否と API の実行可否の両方**に用いる。
画面側のボタン活性制御は**誤操作防止の補助**であり、**最終的な可否はサーバ側で決める**。
必要な権限は**エンドポイントごと**に定める。

## 4. 業務規則

### 4.1 検索

| # | 規則 |
|---|---|
| 1 | 条件は **AND** 結合。空の条件は条件に含めない |
| 2 | メーカーコードは**前方一致** |
| 3 | メーカー日本語名は**中間一致** |
| 4 | 削除含む＝オフのとき、削除済みを除く |
| 5 | 削除含む＝オンのとき、削除済みも含める |
| 6 | 仕掛表示＝**仕掛（登録区分=1）のデータのみ**を対象とする |
| 7 | 既定の並び順：①削除区分（未削除を先）②メーカーコード昇順 |
| 8 | 利用者が指定できるソートは**メーカーコード／メーカー日本語名の 2 項目のみ**。指定時も削除区分を第 1 キーとして維持し、同値時はメーカーコード昇順 |
| 9 | 該当 **0 件**は業務エラー。明細を表示しない |
| 10 | **上限 500 件**を超えた場合は業務エラー。明細を表示しない。**ちょうど 500 件は許容する** |
| 11 | 1 頁件数の候補は **10／20／50／100 件、既定 20 件** |
| 12 | **「仕掛表示」は検索モードの切替（トグル）**。押下で仕掛モードになり、その状態で「表示」を押すと通常モードに戻る。初期表示は通常モード |
| 13 | 削除含む＝オン かつ 仕掛モードのとき、**削除済みかつ仕掛**のデータも対象に含める |
| 14 | ダウンロードは**最後に実行した検索条件**を用いる（画面の現在値は使わない）。**上限超過時は出力しない** |
| 15 | 1 頁件数・削除含むの変更、クリア押下では**自動再検索しない**。「表示」押下で検索する |
| 16 | 0 件の検索も「検索成功」として扱い、複製・戻る・ダウンロード・新規を**活性**にする |

### 4.2 マスタ画面の初期化

| モード | 引き継ぐ値 | 初期状態 |
|---|---|---|
| **新規** | なし | 全項目空。緊急配信オフ。削除欄ブランク |
| **複製** | メーカーコード・日本語名・カナ名 | 上記 3 項目のみ。**緊急配信オフ・削除欄ブランク** |
| **修正** | 対象行の全項目 | 登録値をそのまま表示。**メーカーコードは変更不可** |

複製は**新規登録の下書き**であり、緊急配信・削除の状態は引き継がない。

### 4.3 登録・更新

**新規・複製**（上から順に確認し、違反時点で中断）

1. メーカーコード必須
2. メーカーコード形式（半角英数字、**1〜5 文字**）
3. 緊急配信オンのとき、日本語名・カナ名必須
4. 名称の形式（§4.6）
5. 変更なし（**複製のみ**）→ 登録せずメッセージ
6. 登録確認（No なら中断）
7. **キー重複**——**削除済みのレコードも「存在する」とみなし**、同一コードの登録は不可
8. 登録（INSERT）

**修正**

1. 緊急配信オンのとき、日本語名・カナ名必須
2. 削除をオンにして登録するとき、日本語名・カナ名必須
3. 名称の形式
4. 変更なし → 登録せずメッセージ
5. 登録確認（No なら中断）
6. **被参照チェック（削除をオンにした場合のみ）**
7. **排他**——最終更新日時と改訂番号の**両方が一致**することを要する
8. 更新（UPDATE。削除オンなら論理削除）

**共通**：完了メッセージ後、マスタ画面を閉じ、**最後に実行した検索条件**で一覧を再検索（頁は 1 頁目）。

### 4.4 削除

1. **緊急配信のオン・オフにかかわらず**、日本語名・カナ名必須
2. 名称の形式
3. 削除確認（No なら中断）
4. **被参照チェック**（購入品目別仕入先／原材料仕入単価）
5. **排他**
6. **論理削除**（物理削除しない）
7. 緊急配信が指示されている場合、配信を起動——**判定は削除ボタン押下時点の画面の値**
8. 完了メッセージ → 一覧を再検索

**「削除ボタン」と「削除チェック＋登録」は同一の削除処理**とする（確認項目・被参照・排他・配信条件が同一）。

### 4.5 データの扱い

| # | 結論 |
|---|---|
| 1 | 削除は**論理削除**。**削除済みデータは復活させない**（削除チェックは外せず、登録ボタンは非活性） |
| 2 | メーカー日本語名・カナ名の**重複は許容**（一意制約はメーカーコードのみ） |
| 3 | **送信状態が 9（送信エラー）のレコードは、一覧に名称として表示するのみ**。業務エラー扱いにも登録・更新の抑止にもしない |
| 4 | 監査項目（登録者・登録日時・更新者・更新日時・改訂番号）は**共通部品が付与**。本画面は値を設定しない |

### 4.6 入力チェック

| 項目 | 必須となる条件 | 桁・文字種 | 使用できない文字 |
|---|---|---|---|
| メーカーコード | **新規・複製**では必須（修正では変更不可） | 半角英数字 **1〜5 文字** | なし（文字種の制約のみ） |
| メーカー日本語名 | 緊急配信の指定時・削除時・削除を選択して登録するとき | **UTF-8 で 30Byte 以内**（全角可） | カンマ・アポストロフィ・ダブルクォート・パイプ |
| メーカーカナ名 | 同上 | **半角カナ 15 文字以内**。**濁点・半濁点は独立した 1 文字** | アポストロフィ・カンマ・円マーク・半角スペース |

違反時は該当項目の背景色を変え、フォーカスを移す。**検索条件にも同じチェックを適用する。**
**サーバ側でも同一条件で検査する。**

### 4.7 緊急配信

- 「緊急配信」を付けて登録または削除したとき、**共通部品による配信処理を非同期で起動**する。本画面は受付のみ。
- 配信の**成否は本画面へ返らない**。結果は**送信状態**（0=未送信／1=送信中／2=送信済み／9=送信エラー）で表す。
- 緊急配信を指定するときは**日本語名・カナ名が必須**。
- **業務データの更新を確定した後に配信を起動する**（同一トランザクションにしない）。

## 5. 画面項目

**検索画面の項目は『R60 共通画面項目定義 v2.0』の I-322〜I-354 による**（§9-4）。
以下はその業務的な要約であり、**項目の網羅と細目は同定義を正**とする。

### 5.1 検索画面（33 項目／要約 21 群）

| 群 | 項目 | 要点 |
|---|---|---|
| ヘッダ | 画面タイトル／システム日時／会社・部署・ユーザー名 | タイトル固定値「**メーカーマスタメンテ**」。日時は `YYYY/MM/DD hh:mm:ss`（JST） |
| 条件 | メーカーコード／メーカー日本語名／削除含む／1頁件数 | 削除含むの初期値はオフ。1頁件数の既定は 20 件 |
| 条件 | 仕掛表示／表示／検索条件(非)表示 | 仕掛表示はトグル。条件部の縮小状態は保持する |
| 一覧 | ページャ（上下） | 頁番号は **1 始まり** |
| 一覧 | 複製 | 行未選択では非活性 |
| 一覧列 | コード／日本語名／カナ名／送信状態／削除 | コード・日本語名はリンク（修正画面へ）かつソート可。**送信状態・削除は名称で表示**。**登録ステータスの列は設けない** |
| ボタン | 戻る／業務終了／ダウンロード／新規 | 戻る・ダウンロード・新規・複製は検索成功後に活性。業務終了は常時活性 |

**行選択は単一選択**。リンク押下（修正画面への遷移）は行選択とは別の操作。

### 5.2 マスタ画面（9 項目）

操作モード（新規／複製／修正）、メーカーコード、メーカー日本語名、メーカーカナ名、緊急配信、削除、戻る、削除ボタン、登録ボタン。

- **登録ボタンは常時活性**（押下時に検査する）。
- 削除ボタンは**新規・複製では非活性、修正では活性、削除済みでは非活性**。
- 「変更なし」で終了した場合は**画面を閉じずに留まる**。

## 6. インタフェース

**6 端点**、すべて POST。パスは `/R60Maker/<name>`。要求は `{params: {...}}`、項目名はキャメルケース。

> **例外は `/download` ただ 1 つ。** `/download` は**要求本文を受け取らない**——
> 「最後に実行した検索条件」だけで CSV を作る（下表の `/download` 行のとおり。画面の現在値も
> 要求本文も使わない）。本節冒頭の「要求は `{params: {...}}`」は他の 5 端点に掛かる。
> **2026-11-10 訂正（BUG-005）**：旧文は両方を書いており、実装がどちらを採るか決められなかった
> （実測：`/download` は body を解釈しない。`body_params=[]`）。矛盾していたのは要求書の側である。

| # | 端点 | イベント | 役割 |
|---|---|---|---|
| 1 | `/init` | 1 | 1 頁件数の候補・メッセージ情報を返す |
| 2 | `/search` | 2・3 | 一覧と総件数を返す |
| 3 | `/download` | 8 | 最後に実行した条件で CSV を返す |
| 4 | `/initEdit` | 5・6・7 | モード別の初期値（**排他情報を含む**）を返す |
| 5 | `/delete` | 11 | 論理削除 |
| 6 | `/edit` | 12 | 新規・複製・更新 |

**値の体系**

| 項目 | 値 |
|---|---|
| 検索区分 | `"1"`＝表示／`"0"`＝仕掛表示 |
| モード | `"1"`＝新規／`"2"`＝複製／`"3"`＝修正 |
| 昇降順 | `"asc"`／`"desc"` |
| ソート項目 | `"makerCd"`／`"makerNm"` |
| `errorCode` | **`0`＝正常／`1`＝業務エラー／`9`＝システムエラー**。`errorId` で個別事象を識別 |
| 頁番号 | 1 始まり |

**排他情報**：`lastUpdateDatetime` と `revNo`。`/initEdit` が返し、`/edit`・`/delete` が送る。
**新規モードでは `null` を送り、サーバは比較しない。**

**CSV**：UTF-8（BOM あり）・CRLF・ヘッダ行あり。列は一覧の 6 項目から**排他情報を除いた 5 項目**。

**各 API の前処理順**：**セッション → オンライン可否 → 権限 → 入力チェック**。

## 7. 異常処理

| 事象 | 扱い |
|---|---|
| 検索結果が 0 件 | 業務エラー。明細を表示しない |
| 検索結果が上限（500 件）を超えた | 業務エラー。明細を表示しない。CSV も出力しない |
| メーカーコードが既に存在する（新規・複製） | 業務エラー。メーカーコードを強調表示 |
| 他のマスタから参照されている（削除） | 業務エラー。削除しない。**削除済みの参照元は数えない** |
| 他の利用者が先に更新していた（排他） | 業務エラー。**メッセージのみ**（項目の強調表示はしない） |
| 被参照チェックの共通部品が想定外の結果を返した | システムエラー。処理を中断 |
| 入力チェック違反（画面側） | 該当項目を強調表示・フォーカス移動。**サーバへ送らない** |
| **API の権限検証で権限が不足している** | **業務エラー。処理を中断**。画面のボタン活性制御とは独立に判定 |
| セッション情報が存在しない | セッションエラー画面へ遷移 |
| オンライン利用が許可されていない | オンライン制御エラー画面へ遷移 |
| DB エラー・想定外の例外 | ロールバックし、システムエラー画面へ遷移 |

## 10. 用語

| 用語 | 定義 |
|---|---|
| メーカー | 資材・原材料の供給元となる会社 |
| マスタ | 主データ。業務の基礎となる一覧データ |
| **仕掛** | 登録が**未確定**の状態（登録区分＝1）。確定は夜間の共通処理が行う |
| **確定** | 登録内容が確定し、他のマスタから参照できる状態（登録区分＝2） |
| **緊急配信** | 登録・削除の内容を関連する仕組みへ即時に通知する処理 |
| **送信状態** | 緊急配信の送信状況。0=未送信／1=送信中／2=送信済み／9=送信エラー |
| 削除（論理削除） | レコードを消さずに「削除済み」の印を付けること |
| 排他 | 同時更新時に後からの更新を防ぐこと（最終更新日時＋改訂番号で判定） |
| 被参照 | 他のマスタから参照されていること |
