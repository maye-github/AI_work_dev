> **複数の画面**を 8 工程ぶん走らせて測る。
>
> **★このファイルの役割（2026-10-15 に変更）**：本ファイルは**跨画面の汇总と索引**である。
> 逐節点の「①産出物は使えたか／②どこで詰まったか／③人が直した量／④人版との差」は

## 0. この訓練は何か（charter）

### 0.1 大目標

この一式（骨架・14 agent・4 skill・6 門）は**一度も端から端まで走っていない**。
したがって「具备しているか」への厳密な答えは
**「コードは具备、能力は未検証」**である（`ppt-coverage-assessment.md` §4②）。

机上の評価では「使えるか」は分からない。**実在の歴史案件を題材に走らせ、
フレームのどこが弱いかを実測で見つける**——これがこの訓練である。

### 0.2 機制（★最も誤解されやすいところ）

```
 実在案件の実装 ──(倒推)──► 仮想需求書 ──(凍結)──► 節点1〜8 が新しい産出を作る
      ▲                                                     │
      └─────────────────(事後の対比だけが読む)───────────────┘
```

1. 題材は**実在の R60 案件**（`D:\AI_work`。56 画面）。まず **1 画面（R60Login）で垂直に貫通**させ、
   人の確認を得てから横へ広げる。
2. **手元にきれいな顧客要求書は無い**（実在案件には無いのが普通。顧客が持っているのは動いているシステムである）。
   そこで**実在資産（設計書・実装）から要求を倒推して「仮想需求書」を作る**。
   担当は `virtual-requirement-author`、根拠は `reports/drill/<module>/provenance.yaml` の台帳に残す。
   **倒推は「要求書を作る」ところで止まる。**
3. 要求書を**凍結**（`freeze.yaml` に `sha256`）し、**節点 2〜8 は実在資産を読み返さない**。
   節点 2〜8 の産出は**すべて新規**である。
4. **人版（実装）は「答案」であって「入力」ではない。**
   読むのは**事後の対比（`drill-comparator`）だけ**。
   （A-22 逐語：「既存資産は「答えの出所」ではなく「客户要求的材料」」）
5. 差分を**帰因分類**（`R`/`A1`/`A2`/`A3`/`G1`/`G2`/`D`/`H`）に振り分けて報告に積む。
   **したがって差分は作業の無駄ではなく測定値である。**

### 0.3 何がどこにあるか

| 物 | 場所 | 誰が読むか |
|---|---|---|
| 実在案件の実装（＝答案） | `D:/AI_work`（**永久に読取専用**） | 倒推のとき と `drill-comparator` **だけ** |
| 歴史案件の知識庫 | `docs/90_knowledge/legacy-r60/` | 同上 |
| 仮想需求書（**凍結済み**） | `tutorial/<案件>/节点1_需求/00_输入_客户需求书.md` | **節点1〜8** |
| 倒推台帳・凍結記録 | `reports/drill/<module>/` | `drill-comparator` と次の画面を起こすとき |
| 節点 2〜8 の産出 | `docs/20_`〜`docs/70_`・実装コード | 次工程 |
| 訓練報告 | `reports/drill/<module>/comparison.md` | フレームを改善する人（**顧客には出さない**） |
| 本ファイル | ここ | 跨画面の傾向を見るとき |

### 0.4 何を測れて、何を測れないか（誇張しない）

- **測れる**：「同じ要求から AI が設計・製造したとき、人版とどこで分岐するか」、および
  「門番が誤報・漏報したか」。
- **測れない**：「下流が実在資産を読んだが引用しなかったこと」——**呼び出しの監査ログが無い**。
  機械で分かるのは「凍結後に要求書が改変されていないこと」と「実在資産を**引用**したこと」まで。
- **限界**：題材を作る段階で現行を読むため、**汚染ゼロは最初から不可能**である。
  だから**1 画面ではなく複数画面を積む**。かつて `migration` へ舵を切った事故（RC-SK-03）も、
  同じ「実在資産を入力にした」誤りである。
