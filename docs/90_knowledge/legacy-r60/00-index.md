> **立場**：`D:\AI_work` は**他人のプロジェクトの実コードであり、永久に読み取り専用**である。
> 本知識庫は**読んで分かったことを書き留めたもの**であり、向こう側へは一切書いていない。

> `greenfield` では旧システムが存在せず、要件は顧客の言葉から起こす。**旧実装は答えの出所ではなく、
> 要求を書くための材料にすぎない。** `build_mode` の宣言は `docs/00_plan/coach/<module>/case.yml`。

## 1. この知識庫は何のためにあるか

**「このプロジェクトの 56 画面のうち 1 つを、設計書だけを頼りに AI 全链路で作り直し、
人間が書いた版と比べる」**——そのために必要な知識を、**再読すれば済む形**で置いてある。

- **搬入ではない**。設計書・ソースを丸ごと転記したものではない。**横断知識＋画面カード**であり、
  細部は「どこを開けば書いてあるか」を示す。必要になったら原ファイルを読み直す。
- **推測には印を付ける**。文書に明文がある事実と、構造から推測したことを**別の印**で書く（§3）。
- **差異は消さない**。骨架（trans-cosmos-ai）の規則と実物が食い違ったら、**実物を正とし、
  食い違いを [08-deviations.md](08-deviations.md) に残す**。骨架規則の側は**書き換えない**。

## 5. すぐ効く 6 つの事実

再実装を始める前に必ず効いてくる順に並べる。根拠は各ファイルにある。

1. **`extra="ignore"`**（128 箇所）。骨架規則 03 §2 は `extra="forbid"` と書いているが、
   実物の `BaseCamelModel` は **`ignore`** である。**知らずに作ると全 API の挙動が変わる**（【差異】D-1）。
2. **`BaseCamelModel` は共有基類ではない**。**54 個の router ファイルに各 1 回ずつ定義**されている（【差異】D-2）。
3. **分頁は「OFFSET/FETCH ＋ 末尾 ROWID」**。骨架規則 00 §5 は「ROWID 方式を原則」と書くが、
   **実物は `ROWID` 196 箇所に対し `OFFSET` も 41 箇所**（【差異】D-5）。
4. **API は `POST` 一本槍**。354 端点のうち **351 が `POST`**、業務用の `GET` は**1 件だけ**（[06](06-api.md) §2.2）。
5. **設計書は現行 Java の仕様書**であり、新実装の仕様書ではない。`業務処理説明` には
   `execute(ActionMapping, ActionForm, HttpServletRequest)` が出てくる。**読むときは常にこれを意識する**（【差異】D-19）。
6. **画面レイアウト図・画面遷移図は画像**（セルに埋め込まれた画像）で、テキスト抽出できない。
   規則 03 §7.3 どおり、**人の手でテキスト化するまで製造へ投入しない**（【差異】D-18）。
