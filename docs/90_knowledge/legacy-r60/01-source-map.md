# 01 権威源の地図 — `D:\AI_work` のどこに何があるか

> **目的**：画面を 1 枚作り直すとき、「この事実はどこに書いてあるか」を 1 分で引けるようにする。
> **原則**：**日方交付物（`doc/`）が規格の権威**、`Front-end/` と `api/` は**その実装**。
> 両者が食い違ったら**両方を記録**し、勝手にどちらかを正と決めない（裁定：実物を正とし差異を残す）。

---

## 1. リポジトリは 3 つに分かれている

**【実測】** `D:\AI_work` 直下は単一リポジトリではなく、**独立した git リポジトリ 3 つ**の入れ物である。

| ディレクトリ | 中身 | git | 規模（実測） |
|---|---|---|---|
| `Front-end/` | Vue3 + PrimeVue + Pinia + Vite のフロント | 独立 | view 49 本 / component 113 本 / service 56 本 |
| `api/` | FastAPI + SQLAlchemy + oracledb のバック | 独立 | `fastapi_oracle_pjt/app/` に router 57 本 / 端点 354 |
| `doc/` | **日方から受領した交付物**と社内調査資料 | 独立 | 下記 §2 |

- 起動・ビルド手順は**それぞれのリポジトリの README** にある（`api/README.txt` 等）。
- **【推測】** `Front-end` と `api` は同一案件の表裏であり、`doc` はその上流。3 つをまたぐ単一のビルドは無い。

## 3. `YYYYMMDD_連携` 批次の扱い（★誤解しやすい）

**【実測】** `doc/02_INPUT/` 直下に `YYYYMMDD_連携` という**日付つきディレクトリが 65 個**ある
（`20260407_初回連携` 〜 `20261006_連携`。`202060804_連携` という日付が崩れた名前も 1 つある）。

- これは**日方からの投函を日付ごとに丸ごと入れた箱**であり、**過去分の積み上げ**である。
- **同じ成果物が複数の批次に重複して存在する**。**古い批次と新しい批次のどちらが正かは、
  ファイル名の `_v1.0` / `_v1.1` と `変更履歴` シートで判断する。**
- **【推測】** 最新批次が全体の最新状態とは限らない（画面単位で改版されるため）。
  **画面を 1 枚作るときは、その画面の設計書を全批次から探して最も新しい版を使う。**

> ⚠ **やってはいけないこと**：`10.規約` 等の最新版だけを見て、古い批次の中にしかない改版を見落とすこと。
> 逆に、古い批次の版を掴んで最新版の規約と混ぜること。**必ず `変更履歴` シートで版を確認する。**

## 5. `doc/OLD/`・`91.現行ソース/`・`92.現行DB構築/` — 「現行系」との分離（★最重要の注意）

**この 3 区画は「今回作り直す新システム」ではなく、「作り直しの対象＝現行システム」である。**

| パス | 中身 | 誤るとどうなるか |
|---|---|---|
| `02_INPUT/91.現行ソース/` | 現行 **Java** ソース（`生産系共通マスタ_JAVAソース.zip` 等） | これを読んで作ると **Struts の写経**になり、Vue3/FastAPI の要件を満たさない |
| `02_INPUT/92.現行DB構築/` | 現行 **PL/SQL・DDL**（zip）・コード値/区分値定義 | 同上（DB 側はほぼ流用だが、判断が必要） |
| `doc/OLD/` | 旧系統区・`VUE3+fastAPI.xlsx`・サンプル zip・新旧比較表 | 「前の試み」が混ざる。**現行版の規格ではない可能性がある** |

> ★ **設計書（`50.設計書/画面設計書/*.xlsx`）も「現行仕様の記述」である**。
> `業務処理説明` シートには `execute(ActionMapping mapping, ActionForm form, HttpServletRequest req…)`
> という **Struts/Java の署名**が現れる（**実測**）。**設計書＝規格、既存コード＝規格の一実装**。
> 「重做」とは、**現行 Java の仕様を Vue3/FastAPI で再実装すること**を指す。

## 8. 読み方の作法（読み取り専用の掟）

1. **`D:\AI_work` へは一切書かない。** Read / Grep / Glob / `git ls-files` / ディレクトリ一覧 /
   `py -3 -m tools.legacy`（xlsx 抽出）**のみ**を使う。
2. **`.env` の中身は読まない**（存在と git 追跡の有無だけ見る）。
3. **読むたびに `git -C <repo> status --porcelain` が空であることを確認**できる。
   空なら「只读未被破坏」の証拠になる。
4. **抽出物は `D:\AI_work_dev\` の下にだけ置く**。`tools.legacy.xlsx_text.guard_output()` が
   読み取り専用領域への出力を**書く前に拒否**する（自衛策）。
