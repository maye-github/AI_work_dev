このディレクトリは `/trans-cosmos-ai-lifecycle-coach` の進捗記録である。**手で編集しない**（編集はコーチ経由で行う）。

```
coach/
└── <module>/              ← 一モジュール = 一ワークスペース
    ├── case.yml           ← ケース情報（チーム・種別）
    ├── n01.yml … n08.yml  ← 1 ノード = 1 ファイル（★ 衝突を防ぐ分割）
    ├── n09.yml            ← 旁路環（变更・指摘）。1 件 = 1 項。**第 9 の工程ではない**
    └── handoff.md         ← 交接卡（換人・文脈が埋まったとき機械生成）
```

**n09.yml は工程ではない。** 8 工程の外側を回る環であり、入口は発話 `指摘` だけ、
出口は「戻るべきノード（n01〜n08 のいずれか）」。直列に n08 の後ろへ繋がないこと（`SKILL.md` §3.0）。

**なぜ 1 ノード 1 ファイルか**：3-5 人が同時に開発するとき、1 ファイルを共有すると後から書いた人が
上書きする。1 ノード = 1 ファイルなら同一モジュール内でも衝突しない。総索引は作らない（索引が衝突源になる）。

**仕様の唯一真源**：`.claude/skills/trans-cosmos-ai-lifecycle-coach/SKILL.md` §4。

## ここを触る前に知っておくべき 3 点

1. **鍵名の罠**：`docs/00_plan/coach/**` は `trace_check` gate1 の**豁免区ではない**。
   `id` / `*_id` / `*_ids` / `ids` で終わる鍵を作ると野号判定になる。台帳の Q-ID は **`q_ref`** で指す。

2. **阻塞の権威は `docs/00_registry/ids.yml`**。ここにある `state: blocked` と `open_questions` は
   **その写し（表示態）**であり、食い違ったら台帳を正とする。判定は人が実行する:
   ```
   py -3 -m tools.registry blockers
   ```

3. **発号・状態遷移・回答は人が `tools.registry` で行う**（コーチもこのディレクトリの編集者も代行しない）:
   ```
   py -3 -m tools.registry alloc Q --key "<業務鍵>" --kind question --block --relates-to <ID> [--apply]
   py -3 -m tools.registry answer <Q-ID> --text "<回答>" --by <人>
   ```
   `--apply` を付けない限り**書かれない**（差分が出るだけ）。
