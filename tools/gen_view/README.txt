gen_view — 節点成果物 .md → 人向け閲覧ビュー (HTML) の変換ツール
================================================================

【何のためにあるか】
  節点成果物の .md は「機読源」と「人看版」を兼ねている。
  機読源としては「全・省略なし・来源付き」が正しいが、そのままでは
  6 列の広い表が折り返されず、肉眼でのレビューがつらい（特に
  輸入項 6 列・待確認事項 6 列は、人が最も見たい表なのに読めない）。
  本ツールは同じ .md から閲覧専用の HTML を作り、
  機読源を一切変えずに可読性だけを上げる。

  実行:
    python -m tools.gen_view tutorial/R60Login/节点1_需求/03_客户確認依頼書（AB類）.md
  出力:
    同ディレクトリに同名の .html（ダブルクリックでブラウザ表示／Ctrl+P で PDF 化）
    [gen_view] rendered: ... -> ...
    [gen_view] sections=11 tables=11

  オプション:
    -o/--out PATH   出力先を指定（例: -o reports/view/node1.html）
    --title TEXT    ページタイトル（既定: 入力ファイル名）

【単一ソース原則（FR-3）】
  本ツールは「生成物」であり、機読源ではない。
  機読源は .md / .yaml のまま。本ツールは読むだけで、書き戻さない。
  生成された .html を手で編集してはならない。
  人からの修正は必ず機読源へ入れ、再生成する。
  （gen_formal が日文 Excel について定める原則と同一）

【何をするか】
  - ブロック: 見出し（#〜######）／引用（>）／箇条書き／番号付きリスト／
    チェックボックス（- [ ] ・ - [x]）／パイプ表／水平線／コードフェンス
  - インライン: **強調** / `code` / [link](url)
  - 見出し語から自動でセクションを色分け＋チップ表示
      待確認・確認事項        → ★ 要拍板（アンバー）
      Non-Goals・不做         → 範囲外（グレー）
      異常・錯誤              → 異常（レッド）
      背景                    → 前提（ブルー）
      業務規則                → 業務規則（グリーン）
      輸入項・輸出項          → 項目定義（パープル）
      受入 / トレーサ / 生成メモ → 各色
    ※「要拍板」の節は人が判断すべき箇所なので、自動で目立たせる
    ※ どの語をどの色に割り当てるかは render.py の `_SECTION_RULES` で調整する
  - 表の第 1 列見出しが Q-* / 異常* / Non-Goal* の表は、行も色分け
  - 目次（2 列組み）を自動生成
  - 先頭に「これは生成物。直接編集しない」警告帯を常時表示

【表示言語（2026-10-26 追加）】
  - 出力が `*.zh.html`、または入力が `*.zh.md` のとき、**画面付属文言（chrome）を中文**にする:
    `<html lang="zh">`／目次＝「目录」／警告帯・フッタ・チップの表記。
  - それ以外は日本語 chrome（従来どおり）。**本文は決して翻訳しない** ——
    翻訳は入力の `.zh.md` を書く人の仕事であり、本ツールは描画だけを行う。
  - 実装: `render.py` の `_UI`（chrome）と `_CHIPS_ZH`（チップ）。本文の語彙には触れない。
  - **2026-10-27 修正**: 見出し（h2）のチップだけ日本語固定になっていた不具合を直した。
    `render_markdown()` は `chips` を引数で受け、`build_html()` が選んだ表を渡す。
    **中文ビューでは目次も見出しもチップも中文**になる（`--self-test` に 3 項目追加。18/18）。
    既に生成済みの `.zh.html` は**作り直すまで古いラベルのまま**である（本文は正しい）。
  - **未解決（既知の制限）**: セクションの色分けは日本語の見出し語（`_SECTION_RULES`）で判定するため、
    **中文の見出しには色が付かない**（`plain` 扱い）。本件の修正前から同じであり、悪化はしていない。

【Phase1 の制限】
  - 入力は .md（人が読む方）のみ。.yaml からの直接レンダリングは Phase2 で対応。
  - 入れ子リスト（インデント 2 段以上）は未対応（フラットに描画）。
  - 依存は標準ライブラリのみ。CSS は埋め込み（外部リソース非依存, NFR-6）。

【注意】
  - これは可読性を上げる道具であり、レビューの「合格条件」ではない。
    合格判定は各節点の審査清单（ノード1・2 は `02_確認事項一覧.md`、
    ノード3〜8 は入力模板末尾の `human_review_required`）と
    `py -3 -m tools.trace_check --strict` で行う。
  - 顧客向けの確認媒体は本ビューではなく、gen_formal が生成する
    日文正式 Excel（Phase2）。顧客への問い合わせは「確認依頼書／指摘シート」で行う。
  - 日本語 Windows のコンソール（cp932）は成果物パスに含まれる簡体字
    （例: 节点1_需求）を表現できず落ちるため、標準出力は UTF-8 へ寄せている。
    ファイル出力は常に UTF-8。
