# 知识库使用手顺（新手版）

> **一句话**：想知道以前怎么做的，问它；想把东西交出去，它替你把关。
> **但它不会主动开口——你不问，它不说话。**

这份文档写给第一次用的人。**你不用记任何命令**，会用中文说话就行。
每一节都是「什么时候用 → 你说什么 → AI 做什么 → 你拿到什么」。

---

## 0. 先搞懂三件事（2 分钟）

### 0.1 库里分两层

| 层 | 放什么 | 现在有多少 |
|---|---|---|
| **公司级** | 换个客户还成立的东西：模板、规约、画面模式、通用术语 | 30 篇 |
| **项目级** | 这个客户自己的事实：画面卡、模块卡、审查记录、旧设计 | 85 篇 |

（数字会变。问一句「**知识库现在什么状态**」我就报当前值。）

**为什么分两层**：公司级谁都能查；项目级只有该项目的人能查。混在一起，A 客户的东西就会被 B 客户看到。

### 0.2 它和「搜索」不一样

普通搜索给你一堆链接；这个库给你**一段有出处的结论**，并告诉你**这个结论有多可靠**（见 §3）。

它也不会主动推给你。**你不问，它不说话。**

### 0.3 三个词，认识一下就够了

| 词 | 说人话 |
|---|---|
| `draft` / `open` | 草稿 / 可检索。机器抽出来的东西先是草稿，**人看过才变可检索** |
| `doc_id` | 每条知识的名字，比如 `TPL-DESIGN-BASIC-001`。引用它，就等于指到那一条 |
| `ingest` | 入库。**文件改了不跑这一步，等于没改** |

## 1. 五步上手（10 分钟）

| 步 | 做什么 | 怎么做 |
|---|---|---|
| 1 | 报上你是谁（只做一次） | 跟我说「**我是李**」 |
| 2 | 问一句 | 「**查知识库：以前的一览画面怎么做**」 |
| 3 | 看结果 | 先看有没有 `【推測】`，再看 `doc_id` |
| 4 | 换说法再问 | 中文随便问，系统自己补日文术语 |
| 5 | 查不到就说查不到 | 不要说「库里没有」，先按 §4 排查 |

> **别把它当搜索引擎，当"老同事"。**
> 老同事不会主动找你，但你问对了，他会告诉你上次是怎么做的、当时踩了哪个坑。

## 2. 按功能分的七件事

下面每一节都是一个完整功能。**你只要看「你说什么」，剩下的 AI 做。**

---

### 功能 ①　查：这件事以前怎么做的

**什么时候用**：接到新画面、新功能，不想从零想。

> **你说**：「查知识库：以前的一览画面怎么做」
> **或**：「这个有没有先例？」

**AI 会做**：按中文词去搜（自动补日文术语），按相关度返回，并标出**依据强弱**。

**你拿到**：

```
[PAT-SCREEN-001] 一覧検索画面の標準パターン —— 条件部 + 结果部怎么摆
[r60-001-screens-r60area] 某个真实画面当时怎么设计的
```

**注意**：出现 `【推測】` 的条目**别当结论**——那是文里没写、系统推出来的。

---

### 功能 ②　找：模板、共通部品、规约

**什么时候用**：要写设计书、要写代码。

> **你说**：「有没有基本设计书的模板」
> **你说**：「R60 的共通部品有哪些」
> **你说**：「编码规约在哪」

**你拿到**：

| 你要的 | 会给你 |
|---|---|
| 基本设计模板 | `TPL-DESIGN-BASIC-001`（9 节骨架，照着填） |
| 详细设计模板 | `TPL-DESIGN-DETAIL-001` |
| 测试用例模板 | `TPL-TEST-CASE-001` |
| 结合测试模板 | `TPL-INTEGRATION-TEST-001` |
| 共通部品对应表 | `r60-001-standards-r60common-map`（16 个代表函数，什么场景调哪个） |
| 编码规约 | `STD-CODING-001` |

**省掉的事**：不会重复造一个已经有现成的函数。

---

### 功能 ③　建：给一个新项目开知识库

**什么时候用**：来了一个新客户 / 新项目，要开始攒知识。

> **你说**：「我要建一个新项目的知识库。项目叫『受注管理システム』，ID 用 P-ABC-001。」

**AI 会做**：用三个信息（ID、名称、责任人＝你）建好文件夹，并登记权限。

```
tools/kb-platform/repo/projects/P-ABC-001/
├── sources/     ← 你放原始资料（xlsx/docx/pdf/md/txt）
├── extracted/   ← 机器抽出来的文字（草稿，还不能搜）
├── knowledge/   ← AI 整理好的知识（人确认后可搜）
├── modules/  screens/  standards/  playbooks/  glossary/  review/  chunks/
```

**你拿到**：一句「建好了」，以及下一步该干什么。

**注意**：目录建好是**幂等**的——重复跑不会覆盖你已经放进去的东西。

---

### 功能 ④　加：把 Excel / Word / PDF 放进去

**什么时候用**：客户给了一堆旧资料。

**你只需要做一件事：把文件丢进 `sources/`**，然后说一句：

> **你说**：「把 sources 里的资料导入知识库」

**AI 会做**（分四步，中间会停下来等你）：

| 步 | AI 做什么 | 要你做什么 |
|---|---|---|
| 1 | 把原稿转成 `.md`，放进 `extracted/`，标成**草稿** | — |
| 2 | 给你一份报告：抽了几张表、几行、几字、哪里有警告 | **对一下原稿有没有抽错** |
| 3 | 你确认后，把草稿改成**可检索** | **这一步必须你点头** |
| 4 | 建索引，能搜了 | — |

**报告长这样，重点看这三行**：

```
[P-ABC-001] 2 件
  ○ ログイン仕様.docx → login-spec.md  (段落 2 / 表 1 / 字 57)
       ⚠ 抽出が極端に短い — 図や画像だけの可能性があります
  ○ 画面項目一覧.xlsx → screen-items.md  (sheet 1 / 行 6 / 结合 1 / 字 137)
       ⚠ 結合セル 1 箇所 — 結合された内容が落ちていないか確認してください
```

| 看到 | 意思 |
|---|---|
| `sheet 3 / 行 120` | 原件 3 张表、抽出 120 行——**对一下有没有少张** |
| `结合 14` | 合并单元格 14 处，**最容易丢内容**，抽查这里 |
| `字 57` | 抽出字数。**太少说明原文是图片**，得人工处理 |

**为什么草稿不能直接搜**：

> 机器抽错（表格错列、合并单元格丢内容、PDF 版式错位）是常事。
> 错的東西一旦能搜到，就会被 AI 引用、复制、再包装。**所以必须有人对一眼。**

**支持的格式**：`.xlsx` `.docx` `.pdf` `.md` `.txt`
（PDF 需要机器上装了 `pdftotext`；没有会明确报错，不会静默失败。）

**改了原件怎么办**：再跑一次导入。它会发现内容变了，**自动退回草稿**，让你重看。

---

### 功能 ⑤　用：做 8 个工程节点时引用先例

**什么时候用**：你在跑那套 8 工程流程，每个节点都要出承认版。

> **你说**：「节点 3 该引哪些先例？」
> **或**：「帮我找这个主题的先例」

**AI 会做**：告诉你**这个节点必须读哪些条目**，然后帮你找候选，写进文档的 `kb_refs` 字段。

**你拿到**：一段写好的引用清单。

```yaml
kb_refs: [TPL-DESIGN-BASIC-001, r60-001-screens-r60login]
```

**规矩有两条**：

| 写法 | 什么意思 |
|---|---|
| ✅ `TPL-*`（模板）、`PAT-*`（模式）、`r60-*`（案件事实） | **先例**——照着抄/对照的对象 |
| ⚠️ `STD-*`（规约） | **遵守的证明**，不是先例。规约是"照做"，不是"参考" |

**没有先例怎么办**：写 `kb_refs: []`，并在「未确定事项」里说明为什么没有。**不要留空不写**——留空和"没找"看起来一样。

**这道检查过不去，节点承认不了。**

---

### 功能 ⑥　交：项目结束后，把有用的升格为公司级

**什么时候用**：一个项目做完了，想把「以后别的项目也用得上」的东西交出去。

> **你说**：「帮我看看哪些可以升格」

**AI 会做**：出一张**评审表**，分成四节：

| 节 | 内容 |
|---|---|
| §0 | 公司级现在有什么（按类型分类） |
| §1 | 候选清单：每条给**建议 + 理由 + 脱敏后还剩几个问题** |
| §2 | 每种建议对应该做什么 |
| §3 | 脱敏还缺哪些词（要补进对照表） |

**建议只有 5 种**，每条都带理由：

| 建议 | 意思 |
|---|---|
| `昇格可` | 可以直接升 |
| `雛形のみ` | 内容是这个项目的事实，只能抽「形」 |
| `要補表` | 先把缺的词补进脱敏对照表 |
| `見送り` | 建议别升（但你可以覆盖） |
| `要人判断` | 不属于标准/术语/模板，得人看着定 |

**判定有 5 条**（规则正本 `promotion-criteria.md`）：

| # | 条件 | 谁来判 |
|---|---|---|
| ① | 顾客非依存（不含客户名/系统名/函数名） | 机器查形态，**人看语义** |
| ② | 有出处（哪份原稿的哪一节） | 机器 |
| ③ | **第 2 个项目用过** | 机器查，**但只是建议** |
| ④ | 形可复用（模板/规约/术语） | 机器 |
| ⑤ | 已脱敏（检查 0 件） | 机器 |

> **③ 是建议，不是闸门。** 你判断某条确实通用，照样可以升——工具只会把它标成 `雛形のみ`。

**然后你会走这条流程**（AI 会一步步带你）：

| 步 | 谁做 | 做什么 |
|---|---|---|
| 1 | **你** | 在评审表上勾选要升的条目 |
| 2 | **你** | 把草稿替换回原稿（**不能跳**，见下） |
| 3 | AI | 生成计划文件 |
| 4 | AI | 校验计划（不写任何东西） |
| 5 | **公司负责人** | 执行落库（权限卡在这一步） |
| 6 | AI | 更新索引 + 建结案记录 |

> **为什么第 2 步不能跳**：落库命令只负责「搬文件」，**不会替你改字**。
> 原稿里如果还写着 `R60`，搬过去的就是带 `R60` 的版本。所以现在是硬拦：
> `移送元がまだ脱敏されていません（要修正 37 件）`——不换就不让搬。

**为什么要脱敏**：公司级是所有项目共用的。客户名、人名、系统名混进去，等于把 A 客户的资料给 B 客户看。

**脱敏靠两张表**（都在 `tools/kb_local/`）：

| 文件 | 作用 |
|---|---|
| `promote_map.txt` | 替换表：`原词 => 替换成` |
| `promote_denylist.txt` | 屏蔽词：只要出现就拦下（客户名、人名） |

> ⚠ **现在这两张表是**模拟数据**（`朝日サンプル社`、`山田太郎`）。
> 真案件上必须先换成真名，否则脱敏等于没做。

**有两类东西机器处理不了，只能人来**：

1. **`file:line` 引用**（`r60util.py:293`）——它不是"词"，是实现在哪。要人抽象成「共通ヘッダ部品」这类说法。
2. **语义泄漏**——某条知识形态全干净，但内容只有这家客户才有。机器看不出来。

---

### 功能 ⑦　防：发客户前，查有没有混进内部的东西

**什么时候用**：要给客户发资料，怕里面混了内部的东西。

> **你说**：「这份能不能发」+ 文件名

**AI 会做**：拿这份文件和库里标成 **L40（`client_only`，仅限客户侧）** 的文档比对，
**连续 20 字以上相同**就报出来（阈值可调）。

**注意**：**它不下结论。** 发不发你决定，它只把证据摆出来。
另外它只抓「长段复制」——**改写过的内容抓不到**，别把它当唯一的防线。

## 3. 看结果：可信度标记

每条结果前面会有一个标记，**这比内容本身更重要**：

| 标记 | 含义 | 怎么用 |
|---|---|---|
| `【推測】` | 文里没写，是推出来的 | **别当结论**，要另行确认 |
| `【差異】` | 文里登记了不一致 | 看差异内容再判断 |
| `[文書]` | 有文档依据 | 可用 |
| `[実測]` | 看过实装确认的 | **最可靠** |
| `[摘要]` | 为检索重写过的摘要（非原文） | 用它找到位置，**结论回正本确认** |

出现 `【推測】` 时，末尾会多一行提示：「確定値として使う前に別途確認してください」。

---

## 4. 查不到怎么办（按顺序排查）

| 顺序 | 先查这个 | 为什么 |
|---|---|---|
| 1 | **身份设了吗** | 没设 `whoami` 只能看到公司级，项目知识一条都出不来 |
| 2 | **换两次说法** | 系统按**字面**匹配，不懂意思。用库里常见的词更容易命中 |
| 3 | **是不是 xlsx/pdf** | 库里**只索引 `.md`**。原件要按功能④导入才能搜 |
| 4 | **改过文件忘入库** | 问一句「索引是最新的吗」，红了就重新入库 |

**查不到 ≠ 没有。** 说「这个说法查不到」，别说「库里没有」。

---

## 5. 谁能改什么

| 事 | 谁 | 在哪登记 |
|---|---|---|
| 公司级增删改 | 公司负责人 | `owners.yaml` → `company.owner` |
| 项目级增删改 | 该项目 PM | `owners.yaml` → `projects.<P>.owner` |
| 谁能读哪个项目 | 同上 | `owners.yaml` → `projects.<P>.members` |
| 升格落库 | 公司负责人 | 执行 `apply` 时校验 |

**`null` = 冻结，不是"谁都能改"。** 没任命就等于谁都不能改。

> **你说**：「这些文件我有权限改吗？」
> **AI 会做**：拿你当前的改动去对权限表，逐条告诉你哪些超界。

> ⚠ **这是提交前的提醒，不是文件锁。** 能打开目录的人照样能看、能改。
> 真要保密，得把案件放到只有该项目组能访问的位置——那是文件系统那边的事。

---

## 6. 每周 10 分钟巡检（可选）

> **你说**：「跑一下知识库巡检」

AI 会跑 6 项检查并报结果：

| 检查 | 看什么 | 红了怎么办 |
|---|---|---|
| 索引新鲜度 | 文件改了有没有入库 | **立刻重新入库**（否则搜到的是旧内容） |
| 格式 | 字段有没有填坏 | 按提示补 |
| 检索质量 | 能不能搜到该搜的 | 看是哪类词搜不到 |
| 出处 | 公司级有没有写来源 | 补 `source_project` |
| 权限表 | `owners.yaml` 有没有写坏 | 修 YAML |
| 引用统计 | 每条知识被引用几次 | **长期 0 次的，就是"该删"或"该用起来"的候选** |

## 7. 命令速查（平时不用看）

> 上面每一节，你只要说一句就行。这一节是给「想自己动手 / 要排错」的人看的。

**所有命令都在仓库根目录（`src`）跑。** 在 `tools/` 里跑会报 `No module named 'tools'`。

### 7.1 日常

| 用途 | 命令 |
|---|---|
| 设身份（只做一次） | `py -3 -m tools.kb_local whoami --set <你的名字>` |
| 查 | `py -3 -m tools.kb_local search "<词>" --as <人> [--project <P>]` |
| 只查公司级 | `py -3 -m tools.kb_local search "<词>"` |
| 中日对照表 | `py -3 -m tools.kb_local synonyms` |
| 库里有什么 | `py -3 -m tools.kb_local stats` |
| 索引新鲜度 | `py -3 -m tools.kb_local freshness` |
| 格式检查 | `py -3 -m tools.kb_local lint` |
| 检索质量 | `py -3 -m tools.kb_local eval --all` |
| 出处点检 | `py -3 -m tools.kb_local extra report` |
| 对外文件检查 | `py -3 -m tools.kb_local external-check <文件>` |

### 7.2 建库 / 加资料

| 用途 | 命令 |
|---|---|
| 建新项目容器 | `py -3 -m tools.kb_local project-init --id <P-ID> --name "<案件名>" --by <PM>` |
| 导入资料（预演） | `py -3 -m tools.kb_local import --scan --by <PM> --dry-run` |
| 导入资料（真跑） | `py -3 -m tools.kb_local import --scan --by <PM> [--project <P>]` |
| 入库建索引 | `py -3 -m tools.kb_local ingest --prune` |
| 建空术语表 | `py -3 -m tools.kb_promote init-glossary --project <P> --by <PM> --apply` |

### 7.3 8 节点引用先例

| 用途 | 命令 |
|---|---|
| 这个节点该引什么 | `py -3 -m tools.kb_refs show --node <N>` |
| 这个节点的必读条目（带摘要） | `py -3 -m tools.kb_local node-brief --node <N>` |
| 先例候选 | `py -3 -m tools.kb_refs suggest --project <P> --query "<主题>"` |
| 检查一份 | `py -3 -m tools.kb_refs check <承认版> --node <N>` |
| 检查全部 | `py -3 -m tools.kb_refs scan` |
| **反查：这条被谁用过** | `py -3 -m tools.kb_refs cited <doc_id>` |
| **从没被用过的** | `py -3 -m tools.kb_refs cited --zero` |

### 7.4 升格

| 用途 | 命令 |
|---|---|
| 列候选 | `py -3 -m tools.kb_promote candidates --project <P>` |
| **出评审表（建议 + 理由 + 勾选栏）** | `py -3 -m tools.kb_promote review --project <P> --as <人>` |
| 勾选结果 → 计划文件 | `py -3 -m tools.kb_promote review --project <P> --as <人> --plan-out <plan.yaml>` |
| 校验计划（不写盘） | `py -3 -m tools.kb_promote plan --from-plan <plan.yaml> --by <人>` |
| 抽模板（只留形） | `py -3 -m tools.kb_promote skeleton <成品.md> --out <模板.md> --source-project <P>` |
| 查匿名化 | `py -3 -m tools.kb_promote check <文件>` |
| 生成脱敏草稿 | `py -3 -m tools.kb_promote draft <文件>` |
| 屏蔽词候选 | `py -3 -m tools.kb_promote denylist --project <P>` |
| **落库（公司负责人）** | `py -3 -m tools.kb_promote apply --from-plan <plan.yaml> --by <公司负责人> --apply` |
| 结案记录 | `py -3 -m tools.kb_promote close --project <P> --apply --by <PM>` |
