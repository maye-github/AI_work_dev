# テストケースの分類と最低比率（正常 3・境界 2・異常 3）

> **本条は要約であり、正本ではない。** 正本は `.claude/rules/04-testing.md` §2〜§6。

## 1. 最低比率

1 つの要求（R-ID）または機能（F-ID）に対する TC は、**最低 8 件**を下限とする。

| 分類 | 最低件数 | 意図 |
|---|---:|---|
| 正常 | 3 | 主要業務フローの正常系（一覧／新規登録／既存修正 など） |
| 境界 | 2 | 桁数・件数・上限下限の**ちょうど境界**、排他・件数 0 件 |
| 異常 | 3 | エラー系・制約違反。**必ず E-ID を 1 つ以上持つ** |

境界は「ちょうど境界」を突く。**もう一歩外**は異常系へ寄せる（境界に数えない）。

## 2. 三つの観点技法

| 技法 | 適用対象 | 例 |
|---|---|---|
| 同値分割 | 入力値域を持つ項目 | コード項目の桁数クラス |
| 境界値 | 桁数・件数・上限下限 | 分割件数のちょうど上限／先頭に不許可文字 |
| デシジョンテーブル | 条件組合せ（権限・フラグ） | 自工場/他工場 × 権限区分 × 操作 のボタン活性 |

採用した技法は `viewpoint` 欄に記録する。条件が組合せ爆発する場合は等価な組合せを縮約しつつ、
**全動作を 1 回以上カバー**する。

## 3. 各 TC が必ず持つもの

- `design_ids`：対象ロジック（L）、製造（D）、**入出力に対応する I-ID**
- `req_ids`：逆参照の要求 ID
- `precondition` / 入力 / 期待出力 / 合否断言ルール

**入出力の I-ID が `design_ids` に無い TC は「何を検証しているか」が追跡できない**ので差し戻し。

## 4. 追跡は双方向で閉じる

前方向 `R → F → I → D/L → E → TC` と、逆方向 `TC → req_ids → 設計 → 要求` の**両方**が途切れないこと。
片方向でも欠けていれば追跡検査は非ゼロ終了。**孤児 ID ゼロ**が合格条件。

## 5. 冪等性と合否

- **再設計しても TC の番号と対応が入れ替わらないこと。** 追加は末尾に足す（既存番号を振り直さない）。
- **TC 設計を確定し、人の承認を経てからテストコードを生成する**（順序を逆にすると手戻りが積み上がる）。
- **合否判定は人が行う。** AI は合否を宣言しない。人の識別子が記録されて初めて「合格」になる。
