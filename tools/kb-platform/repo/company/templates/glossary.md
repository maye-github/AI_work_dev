# 用語集テンプレート（案件専用語の登録と昇格）

> **本条はテンプレートであり、特定案件の用語集ではない。** 例はすべて占位である。
> 記入規則の正本は `tools/kb-platform/kb-policy.md`（機密区分・匿名化・昇格手順）。

## 1. 何のために作るか

同じ語が、客先・設計書・コード・議事録で**違う意味**に使われると、後工程で必ず事故る。
用語集は「その案件ではこの語をこの意味で使う」を 1 箇所に固定するためのものである。

**用語集は辞書ではない。** 一般語（「画面」「一覧」）は載せない。
**その案件でしか通じない語**だけを載せる。

## 2. 載せるもの／載せないもの

| 載せる | 例 | 理由 |
|---|---|---|
| 案件専用の業務語 | 引当、繰越、締め処理 | 一般語に訳すと意味が変わる |
| 画面・帳票の固有名 | 受注一覧、在庫照会 | 設計書とコードで表記が揺れる |
| 社内略語・符丁 | 電帳、口振 | 外部の人には通じない |
| 日英中の対応が決まっている語 | 受注 / Order / 订单 | 翻訳の揺れを止める |

| 載せない | 理由 |
|---|---|
| 一般語（画面・一覧・登録） | 辞書の真似になる。検索の邪魔になる |
| 顧客名・個人名・部署名そのもの | 匿名化前は会社級に出せない（§5） |
| 一時的なプロジェクト用語（今回だけの呼び方） | 2 案件目で使われないものは会社級に上げない |
| コード内の変数名 | 命名規約の仕事。用語集ではない |

## 3. 記入表

1 語 = 1 行。**空欄を残さない**（空欄は「無い」と「まだ書いていない」を区別できない）。

| 用語ID | 用語（原文） | 読み | 中文 | English | 定義（1 文） | 出所 | 備考 |
|---|---|---|---|---|---|---|---|
| TERM-001 | 〈業務語〉 | 〈よみ〉 | 〈中文訳〉 | 〈English〉 | 〈この案件でどう使うか〉 | 〈設計書 §x〉 | |
| TERM-002 | 〈画面名〉 | | | | | | |

- **用語ID** は `<案件>-TERM-<連番>` か、会社級なら `GLO-<領域>-<連番>`。
- **定義は 1 文**。長い説明が要るなら、それは用語ではなく仕様である（設計書へ）。
- **出所** は「どの文書のどこに書いてあったか」。無い場合は「口頭（日付・相手の役割）」と書く。
- **同じ意味の語が 2 つある**場合は、片方を「別名」として備考に書き、**正は 1 つに決める**。

## 4. 置き場所

| 段階 | 置き場所 | `scope` | 誰が更新するか |
|---|---|---|---|
| 案件で使っている間 | `repo/projects/<P-ID>/glossary/` | `project` | 案件責任者（PM） |
| 案件終了後、他案件でも通じるもの | `repo/company/glossary/` | `company` | 会社の責任者 |

**昇格は全部ではない。** 「2 案件目でも使われた語」だけを上げる（`kb-policy.md` §5）。

## 5. 昇格前の匿名化（ここが一番事故る）

会社級へ上げるとき、次を必ず落とす。

| 落とすもの | 例 | 置き換え |
|---|---|---|
| 顧客名・会社名 | 〈顧客名〉 | 「顧客」「取引先」 |
| 個人名 | 〈人名〉 | 「担当者」「承認者」 |
| 案件名・システム名 | 〈案件名〉 | 「受注システム」など機能名 |
| 実データの例 | 〈実在の品番〉 | `COL_1` / `VAL_1` の占位 |

```bash
py -3 -m tools.kb_promote check <このファイル>
```

`【要修正】` が 0 になるまで直す。`【参考】` は例示の可能性があるので人が判断する。
