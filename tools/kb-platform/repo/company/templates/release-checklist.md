# ＜機能名＞ リリース・運用チェックリスト

> **本条はテンプレートであり、特定案件のリリースではない。** 値はすべて `<…>`。
> **リリース判定は人が行う**（紅線③）。AI は材料を揃えるだけ。

## 0. このテンプレートの使い方

- 1 リリース（または 1 機能の投入）につき 1 ファイル。
- 判定欄は**人が署名**する。空欄のままリリースしない。

## 1. リリース判定（すべて満たすこと）

| # | 条件 | 確認方法 | 判定（人） |
|---|---|---|---|
| 1 | 上流の承認版が揃っている（要件・基本設計・詳細設計） | `status: baselined` を確認 | ☐ |
| 2 | 単体テストの合否が人により判定済み | `approved_by` に人の識別子 | ☐ |
| 3 | 結合・総合テストのシナリオを実行し、観測結果がある | IT の実行記録 | ☐ |
| 4 | `trace_check --strict` が Exit 0 | 生出力を添付 | ☐ |
| 5 | `--only-check secrets` が PASS | 生出力を添付 | ☐ |
| 6 | `docs/**` に `.xlsx` が無い（機読源のみ） | `find docs -name "*.xlsx"` = 0 | ☐ |
| 7 | 切戻し手順が用意されている（§2） | 本書 §2 | ☐ |

> **「テストを実行した」と「合格した」は別。** 未実行の項目は「未実行」と書く。緑と読まない。

## 2. 切戻し手順

| 項目 | 内容 |
|---|---|
| トリガー | ＜どの事象が起きたら切り戻すか＞ |
| 手順 | ＜番号付きで。誰が・何を・どの順で＞ |
| データ | ＜戻す／戻さない。戻す場合の根拠＞ |
| 確認 | ＜切り戻し後の確認項目＞ |

## 3. 運用 Runbook

| 項目 | 内容 |
|---|---|
| 監視 | ＜何を監視するか（ログ・アラート）＞ |
| 障害受付 | ＜窓口・時間帯・一次切り分けの期限＞ |
| 連絡 | ＜エスカレーション先＞ |
| 定常作業 | ＜夜間処理・バックアップ等＞ |

## 4. ナレッジの引き継ぎ（結案時）

- 会社級へ上げる候補を `promotion-criteria.md`（5 項）で判定する。
- **1 案件目は上げない。** 2 案件目で使われたものだけを公司級へ。

## 5. 未確定事項の扱い（**この節は承認版に載せない**）

起草中に未確定を整理する欄。承認版からは削除する（規則 02 §6.1）。
