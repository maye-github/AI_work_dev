# 成果物の二重化（機読源と日文正式版の二本立て）

> **本条は要約であり、正本ではない。** 定義の正本は `docs/90_knowledge/dual-deliverable.md`、
> 運用の正本は `.claude/rules/00-project-global.md` §11〜§12。食い違ったら正本を採る。

## 1. 二本立ての理由

対日案件では、**内部**は AI が読み書きできる構造化ソース、**対外**は顧客規約に準拠した
日本語の正式成果物、という 2 つの形が同時に要る。

| | 内部（機読源） | 対外（日文正式版） |
|---|---|---|
| 形 | Markdown ＋ YAML front matter | Excel / Word（顧客規約準拠） |
| 用途 | AI の読み書き・差分レビュー・ID 追跡 | 顧客提出・検収・品質記録 |
| 版管理 | Git（差分で見る） | 提出時点の控え |

**単一ソースから生成するから不整合が起きない。** 二重に手で書くから食い違う。

## 2. 禁止する回路と、代わりに使う回路

```
【禁止】機読源 → Excel → 人が Excel 本文を赤字で直す → その Excel を AI に渡して .md へ戻す
```

同一項目が二箇所で定義され、どちらが正か判別できなくなる。

**許可する回路（受控回流）**：正文は**読み取り専用**で渡し、別シートに
「指摘シート／レビュー欄」（行番号・ID 付き）を添える。顧客は**そこにだけ**書く。
AI は**その欄だけ**を読んで機読源を直し、再生成する。

## 3. 生成物の置き場

- `docs/**` に `.xlsx` を作らない（`docs/` は機読源だけを置く場所）。
- 目視用・対外ドラフトは `reports/` 配下に作る。**生成物は手で編集しない**（次の生成で消える）。
- 修正は必ず機読源に対して行い、再生成する。

## 4. 判定に使うときの注意

「AI が出した初稿」と「顧客に納めた正式版」は**別物**として扱う。
レビュー記録に「成果物を確認した」と書くときは、**どちらの形を・いつの版で**見たのかを添える。
