# 受注・在庫引当システム テスト仕様書

## 1. テスト方針

要件定義書（REQ-001）の機能要件と非機能要件を1対1でたどれるように
ケースIDを付ける。設計書にしか書かれていない仕様はテスト対象外とし、
先に設計書へ反映する。

## 2. 機能テストケース

| ケースID | 観点 | 期待値 |
|---|---|---|
| TC-001-01 | 在庫が十分にある | 引当成功、ALLOC_STATUS=1 |
| TC-001-02 | 在庫が不足している | E-1041 を表示し、受注が登録されない |
| TC-001-03 | 引当モード=2 で在庫不足 | 部分引当となり、不足分は未引当で保留 |
| TC-001-04 | 他ユーザが先に更新 | E-1042 を表示し、画面を最新化 |
| TC-001-05 | 引当済み受注の取消 | E-1044 を表示し、取消できない |

## 3. 境界値・異常系

- 引当数量0、引当数量が在庫と同数、在庫より1多い、の3点を必ず試す。
- 同時実行テストは2セッションで同一明細を更新して E-1042 を確認する。

## 4. 性能試験

- 条件: 同時200セッション、受注検索と引当確定を1:1で実行。
- 合格基準: 95パーセンタイルの応答時間が3秒以内であること。
- 試験時間: 30分間継続し、エラー率0.1%未満であること。

## 5. 回帰テスト範囲

引当ロジックに変更が入った場合は、TC-001-01〜05 と性能試験を必須とする。
