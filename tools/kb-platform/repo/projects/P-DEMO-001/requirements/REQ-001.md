# 受注・在庫引当システム 要件定義書

## 1. 目的

受注登録から在庫引当、出荷指示までの業務を一つの画面群で完結させる。

## 2. 対象業務

- 受注登録・変更・取消
- 在庫引当（自動引当／手動引当）
- 出荷指示

## 3. 機能要件

### 3.1 在庫引当

- 受注登録時に、引当可能在庫を確認する。
- 引当可能在庫が不足する場合は、エラーコード E-1041（在庫不足）を返し、
  受注を登録しない。
- 引当モード=2 の場合に限り部分引当を許可する。不足分は未引当として保留する。
- 引当確定後は、引当済み数量を受注数量から差し引く。

### 3.2 引当の優先順位

同一アイテムに複数の受注が競合する場合、引当は次の順で行う。

1. 得意先ランク（高い順）
2. 納期（早い順）
3. 受注番号（小さい順）

### 3.3 受注の取消

引当済みの受注は取消できない。先に引当を解除する必要がある。

## 4. 画面要件

- 受注一覧画面、受注登録画面、引当画面の3画面で構成する。
- 一覧画面は社内標準パターン（PAT-SCREEN-001）に従う。

## 5. 非機能要件

- 応答時間: 通常操作で3秒以内（95パーセンタイル）。
- 同時接続数: 200セッション。
- ログイン失敗が5回連続した場合、当該アカウントをロックする。
- 夜間バッチは日次で在庫を再計算し、差異があればアラートを出す。

## 6. 制約

- 既存の基幹システムとは日次バッチで連携する。リアルタイム連携は対象外。
