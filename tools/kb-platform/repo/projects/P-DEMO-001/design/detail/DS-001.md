# 受注・在庫引当システム 詳細設計書（引当編）

## 1. 処理概要

`/order/register` は 受注登録 → 引当可能在庫の取得 → 引当レコード作成 →
在庫の引当可能在庫更新 の順に処理する。

## 2. T_ALLOC テーブル定義

| カラム | 型 | 主キー | 説明 |
|---|---|---|---|
| ALLOC_ID | NUMBER(12) | ○ | 引当ID（シーケンス採番） |
| ORDER_NO | VARCHAR2(12) | | 受注番号 |
| ORDER_LINE_NO | NUMBER(4) | | 受注明細番号 |
| ITEM_CD | VARCHAR2(12) | | アイテムコード |
| WAREHOUSE_CD | VARCHAR2(6) | | 倉庫コード |
| ALLOC_QTY | NUMBER(10) | | 引当数量 |
| ALLOC_STATUS | CHAR(1) | | 0:未引当 1:引当済 9:解除済 |
| KSN_DAT | TIMESTAMP | | 更新日時（楽観ロック用） |

主キーは ALLOC_ID の単一列。受注明細との一意制約は
（ORDER_NO, ORDER_LINE_NO, ITEM_CD）に置く。

## 3. インデックス

- `IDX_ALLOC_ORDER` : (ORDER_NO, ORDER_LINE_NO)
- `IDX_STOCK_ITEM` : (ITEM_CD, WAREHOUSE_CD)

## 4. 引当可能在庫の算出

引当可能在庫 = 実在庫 − 引当済数量 − 引当保留数量。
計算は SQL 側で行い、アプリ側で再計算しない。画面に表示する値は参考値であり、
登録時には改めてDBの値で判定する。

## 5. 排他制御

更新時は KSN_DAT（更新日時）による楽観ロックを行う。
画面から送信された KSN_DAT が DB の現在値と一致しない場合は、
他ユーザが先に更新したとみなし、エラーコード E-1042 を返す。

## 6. 引当確定SQL

```sql
UPDATE T_ALLOC
   SET ALLOC_STATUS = '1',
       KSN_DAT = SYSTIMESTAMP
 WHERE ALLOC_ID = :alloc_id
   AND KSN_DAT = :ksn_dat
```

更新件数が0件の場合は E-1042 とする。

## 7. エラー時の扱い

- E-1041（在庫不足）はトランザクションをロールバックし、受注も登録しない。
- E-1042（更新済み）はメッセージのみ返し、画面を最新化させる。
