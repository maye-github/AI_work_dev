# 受注・在庫引当システム 基本設計書

## 1. システム構成

フロントエンド（画面）とバックエンド（API）を分離する。
認証は社内SSOを使い、案件側ではトークン検証のみ行う。

## 2. 画面一覧

| 画面ID | 画面名 | 主な機能 |
|---|---|---|
| SCR-001 | 受注一覧 | 検索・ページング・CSV出力 |
| SCR-002 | 受注登録 | 新規登録・引当確認 |
| SCR-003 | 引当 | 引当確定・引当解除 |

## 3. API一覧

| メソッド | パス | 用途 |
|---|---|---|
| POST | /order/search | 受注検索 |
| POST | /order/register | 受注登録と引当確認（同一トランザクション） |
| POST | /allocation/confirm | 引当確定 |
| POST | /allocation/release | 引当解除 |

## 4. エラーコード一覧

| コード | 内容 | 発生箇所 |
|---|---|---|
| E-1041 | 在庫不足 | 受注登録時の引当確認 |
| E-1042 | 他ユーザにより更新済み | 更新処理の排他チェック |
| E-1043 | 得意先がロック中 | 受注登録 |
| E-1044 | 引当済みのため取消不可 | 受注取消 |

## 5. テーブル概要

| テーブル | 用途 |
|---|---|
| T_ORDER | 受注ヘッダ |
| T_ORDER_DETAIL | 受注明細 |
| T_STOCK | 在庫（アイテム・倉庫単位） |
| T_ALLOC | 引当（受注明細と在庫の対応） |

## 6. トランザクション境界

- 受注登録と引当確認は同一トランザクションで行う。
- 引当確定は明細単位ではなく受注単位でコミットする。

## 7. バッチ連携

基幹システムとの連携は日次バッチ（23:00開始）で行う。
連携結果はエラーファイルに出し、翌営業日の朝に運用が確認する。
