# R60SesModel — 検索摘要（80 条）

## R60SesModel の位置づけと規模

`SES-SCR-001` / `screen`

R60SesModel は生産モデルマスタメンテナンス画面で、教材モジュールの複雑・第 1 推奨である。主従 4 画面（検索一覧、明細一覧、ヘッダマスタ項目モーダル、明細マスタ項目モーダル）を持ち、テーブル 6 つ、API 端点 12、設計イベント 28、単体テスト 760 セル（実項目 679）で構成される。簡単モジュール R60Ssk と中等モジュール R60Plc が 1 画面 1 テーブルなのに対し、本画面は親子 2 階層の一覧と各階層のモーダルを持ち、自動採番、再帰解決、ダミーマスタ登録、多テーブル連鎖更新が揃う。前提条件はなし、排他条件はあり、利用対象者は利用権限保持者である。

## 検索一覧の構成（42 項目）

`SES-SCR-002` / `screen`

検索一覧の番号行は No1〜No50 で、見出し行 No1 / 7 / 26 / 45 を除き、欠番 No15 / 19 / 20 / 21 がある。実項目は 42 件（ヘッダー 5、検索条件 14、一覧 18、ボタン 5）。No の最大値 50 とは一致しない。検索条件は生産モデルコード、アイテム名称、削除含む、購入品目コード、購入品目名称、半製品コード、半製品名称、頁件数、仕掛表示、表示、検索条件非表示など 14 項目。一覧は送信、生産モデルコード、生産モデル名、親コード区分、削除の 5 列に複製ボタンと明細ボタンを加える。ソート可能なのは生産モデルコードと生産モデル名の 2 列だけである。

## 明細一覧の構成（30 項目）

`SES-SCR-003` / `screen`

明細一覧の番号行は No1〜No35 で、見出し行 No1 / 3 / 4 / 7 / 30 を除くと実項目 30 件（ヘッダー 1、明細列 24、ボタン 5）。ヘッダーには選択中の生産モデル（親）を表示する。明細列は送信、子コード区分、子コード、子コード名称、所要量、所要量単位、基準値、基準値単位、調達対象外フラグ、展開区分、削除の 11 列が中核である。子コードはリンクになっており、押下すると子のマスタ項目モーダルが修正モードで開く。子コード名称は区分に応じてR60_Get_Hsh_Information_FNC または R60_Get_KonHmk_Information_FNC で名称化する。

## ヘッダマスタ項目モーダル（12 項目・3 モード）

`SES-SCR-004` / `screen`

ヘッダマスタ項目シートの番号行は No1〜No15 で、見出し行 No1 / 3 / 12 を除くと実項目 12 件（ヘッダー 1、入力 8、ボタン 3）。1 つのモーダルを mode 1=新規、2=複製、3=修正で切り替える。操作モードと親コード区分はラベルのみ。親番と枝番は自動採番 OFF の時だけ入力でき、生産モデル名は常に編集できる。半製品コードは自動採番時は読取専用になる。緊急配信と削除は修正モードだけに表示する。ボタンは戻る、削除、登録の 3 つ。半製品コード自動採番は、新規モードかつオプション区分 2（半製品）かつログイン会社が0093 または 0452 の時だけ有効になる。

## 明細マスタ項目モーダル（15 項目・3 モード）

`SES-SCR-005` / `screen`

## 業務処理の流れと判定順

`SES-SCR-007` / `screen`

検索では単項目チェックの後、WHERE を組み立て、同じ WHERE で COUNT(*) を取る。0 件は R60W0010、上限超過は R60W0005。上限は情報ID 000000024 で取得し、取得不能時は 500。既定ソートは DEL_FLG, SES_MDL_CD, ROWID。ページングは OFFSET/FETCH。ヘッダの判定順は、新規・複製が単項目、重複、イベント参照、REG_STS、登録、修正が排他、イベント参照、復活チェック、緊急配信整合、REG_STS、登録である。明細の新規は親存在、単項目、飲料社ルール、イベント参照、重複。修正は復活チェック、親存在、排他、イベント参照。ヘッダ削除は存在、排他、イベント参照、緊急配信対象、子の REG_STS、被参照、多テーブル論理削除、commit の順である。

## 検索条件 14 項目の仕様

`SES-FLD-002` / `field`

検索条件は 14 項目。生産モデルコードは前方一致で検索アイコン付き、アイテム名称は中間一致、購入品目コードと半製品コードは前方一致で検索アイコン付き、それぞれの名称は中間一致である。削除含むが未チェックなら DEL_FLG=0 を加える。１頁件数は情報ID 000000089 で、既定は KOB_KMK_NM_10='D'、無ければ '10'。仕掛表示は search_btn='0' で REG_STS='0' を加え、表示は search_btn='1' で REG_STS を加えない。検索条件非表示はフロントだけで処理する。

## 一覧 5 列・明細 11 列とソート可能列

`SES-FLD-003` / `field`

検索一覧の列は 5 つ。送信、生産モデルコード（リンク）、生産モデル名（リンク）、親コード区分、削除である。複製ボタンと明細ボタンが各行に付く。ソート可能なのは生産モデルコードと生産モデル名の 2 列。明細一覧の列は 11 が中核で、送信、子コード区分、子コード（リンク）、子コード名称、所要量、所要量単位、基準値、基準値単位、調達対象外フラグ、展開区分、削除である。子コード名称は品目なら R60_Get_Hsh_Information_FNC、半製品なら R60_Get_KonHmk_Information_FNC で取得する。

## ヘッダマスタ項目の編集可否

`SES-FLD-004` / `field`

ヘッダマスタ項目は 12 件。ラベルのみは操作モードと親コード区分。新規・複製で編集できるのは親番と枝番（自動採番 OFF 時）と生産モデル名で、半製品コードは自動採番 ON の時は読取専用になる。修正モードだけ編集できるのは緊急配信と削除。ボタンは戻る、削除、登録。新規・複製では削除ボタンが非活性、修正では活性になるが、既に削除済みの行では非活性である。登録ボタンは新規モードでは常に活性、それ以外は権限区分 Y の時だけ活性になる。

## 明細マスタ項目の編集可否

`SES-FLD-005` / `field`

明細マスタ項目は 15 件。ラベルのみは操作モード、子コード名称、コメント挿入 1 / 2。新規・複製・修正で編集できるのは子コード区分、子コード、所要量、基準値、調達対象外フラグ、展開区分。修正モードだけ編集できるのは削除。ボタンは戻る、削除、登録。子コードの隣の検索アイコンは、子コード区分に応じて R60HshSup または R60KonHmkSup を起動する。設計の No13 展開区分の初期値はコピペ誤りで、展開区分自身の値が正である。

## DB モデル 6 テーブル

`SES-FLD-006` / `field`

R60SesModel は 6 テーブルを使う。R60_SES_MODEL_M_TBL は生産モデルの親で 18 列、R60_SES_MODEL_MES_M_TBL は明細で 21 列、R60_SYOHO_M_TBL は処方マスタで 27 列、R60_HAN_SEIHIN_M_TBL は半製品マスタで 62 列、R60_HSH_SES_MODEL_REF_M_TBL は品目・生産モデル参照で 17 列、R60_KJO_SES_MODEL_M_TBL は工場生産モデルで 21 列である。親は INSERT 18、UPDATE 10、DELETE 9。明細は INSERT 21、UPDATE 8、DELETE 8。処方マスタは UPDATE 6 のみ。半製品は INSERT 40、UPDATE 8、DELETE 8。参照は DELETE 4 のみ。工場は UPDATE 4、DELETE 4 である。

## 半製品マスタの 62 列と INSERT 40 列

`SES-FLD-007` / `field`

R60_HAN_SEIHIN_M_TBL は 62 列だが、自動採番時のダミー登録で INSERT するのは 40 列である。残りは DB 既定値に委ねる。明示的に入れる代表値は、GZR_NYU_GRP_CD='50'、CYOT_KBN='0'、HSH_HMK_BNR_CD_1='H000'、_2='1600'、_3='1650'、SUU_TNI_CD='902'、HSH_TYP_CD='9'、KIJ_GNS_KNW_RAT='0'、KNSN_HHO_KBN='1'、SSEI_IST_SKK_SAKE_CD='999'、IST_MES_SAKE_CD='999'、SST_BNR_CD='99'、GNK_RENK_KBN='2'、REG_STS='0'、SEND_STS='0'、SEND_KBN='0'、DEL_FLG='0'、REG_KBN='1'、REG_PGM_ID='R60SesModel' である。62 列表だから 62 列 INSERT と読むと誤る。

## キー列・排他・状態列

`SES-FLD-008` / `field`

R60SesModel のキー列は、親が SES_MDL_CD、子が OYA_CD_KBN と KO_CD_KBN と KO_CD である。状態と排他に関わる列は、DEL_FLG（論理削除）、REG_STS（登録ステータス）、KSN_DAT（更新日時、排他の比較対象）、REV_NO（改訂番号、更新時 +1）、SEND_STS（送信ステータス）、KSN_KBN（オンライン区分）である。親と子の両方が KSN_DAT による楽観ロックを持つ。

## 移送表 12 枚と実テーブル 6 つ

`SES-FLD-009` / `field`

項目移送表は DB1 から DB12 までの 12 枚あるが、実テーブルは 6 つである。DB1 と DB7 が親、DB2、DB8、DB11、DB12 が子、DB3 が処方マスタ、DB4 と DB10 が半製品マスタ、DB5 が品目・生産モデル参照、DB6 と DB9 が工場生産モデルに対応する。1 テーブルにつき登録・更新・削除の操作別にシートが分かれているため、更新列はシートごとに読み分ける必要がある。1 テーブル 1 シートと誤解すると更新列を取り違える。

## 設計に現れる顧客固有の業務定数

`SES-FLD-010` / `field`

設計と実装に現れる顧客固有の定数は、飲料社の会社コード 0093、カルピス社の会社コード 0452、ビール社の工場会社コード 0001、工場コード P030 である。ダミー半製品コードは正規表現 4[A-Z] の 4 桁数字で、範囲は 4A0000 から 4Z9999、枝番は 000 と 001 だけを使う。REG_STS と SEND_STS は 0 と 1 を取り、削除は DEL_FLG=1 の論理削除である。これらの値は設計書と実装の両方に直書きされており、新規構築では設定化を検討する。

## 画面項目シートの設計誤り

`SES-FLD-011` / `field`

画面項目シートには 4 種類の誤りがある。検索 No10 アイテム名称の種別が『ボタン』になっている。明細マスタ No13 展開区分の初期値が『同行の調達対象外フラグ』になっている。検索 No12 と No16 の購入品目コード・半製品コードはエンティティ桁 7、表示桁 6 と書かれ、どちらの桁でチェックするか迷う。検索シートには欠番 No15 / 19 / 20 / 21 がある。これらは番号や種別で機械的に照合すると取りこぼす典型である。

## 項目カードの未確定事項

`SES-FLD-012` / `field`

R60SesModel の項目カードで未確定なのは、一覧で選択した状態をどこに保持するか、処方マスタの自動生成がモジュール外のどこで行われるか、DB10 のダミー初期値の意味、DB5 と DB6 の監査列を更新しない理由である。いずれも設計書だけでは確定できず、実装を読んでも意図までは分からない。人が裁定する必要がある。

## API の共通規約と 12 端点

`SES-API-001` / `api`

R60SesModel の API は HTTP POST / JSON、base path は /api/R60SesModel、要求は { params: {...} } の封筒に入れる。wire は camelCase、内部は snake_case で、BaseCamelModel が変換する。端点は init、search、download、dataInit、initEdit、edit、delete、searchChild、initEditChild、getKonHmk、editChild、deleteChild の 12 である。全端点の先頭で r60util.chk_onl_flg() を呼ぶ。BaseCamelModel は extra='ignore' で、骨架規則の extra='forbid' と異なる。

## init 端点

`SES-API-002` / `api`

POST /api/R60SesModel/init は初期表示を担う。要求は simKbn、loginCmpCd、loginJigCd。simKbn が空なら error_code='3' を返す。応答は error_code、sim_info、jig_list、page_limit_list、default_page_limit、kjo_usr_flg、message_info である。事業場一覧は情報ID 000000375、頁件数は 000000089 で KOB_KMK_NM_10='D' を既定とし、無ければ '10'、工場ユーザーフラグは 000000412 から取る。message_info は 36 件である。R60W0001 はこの 36 件に含まれない。

## search 端点

`SES-API-003` / `api`

POST /api/R60SesModel/search は一覧を検索する。パラメータは simKbn、sesMdlCd、sesMdlNm、konHmkCd、konHmkNm、hshCd、hshNm、btn、isDeleted、currentPage、pageLimit、sortField、sortOrder。btn='0' の時だけ REG_STS='0' を加え、isDeleted が '1' でない時 DEL_FLG='0' を加える。同じ WHERE で COUNT(*) を取り、0 件は R60W0010、上限超過は R60W0005。上限は情報ID 000000024 から取得し、取得不能時は 500。ソート許可は SES_MDL_CD と SES_MDL_NM。抽出列は R60_GET_SELECT_COLUMN_FNC で取る。

## download 端点

`SES-API-004` / `api`

POST /api/R60SesModel/download は直前の検索条件とソート順で CSV を返す。ビュー R60_SES_MODEL_M_VW を使い、R60CsvUtil で CSV 化する。削除条件は is_deleted == '0' の時だけ DEL_FLG を加える点が search と異なる。WHERE 句を f-string で連結し、引用符の二重化は ses_mdl_cd にだけ行う。同じ画面で search は bind、download は文字列連結という不揃いがある。

## dataInit 端点

`SES-API-005` / `api`

POST /api/R60SesModel/dataInit はデータ初期化を行う。sim_kbn が '0'（通常環境）なら R60W0001 で拒否する。通過後、R60L550BBean.do_r60l550b() を SES と SES_MES の 2 回呼び、commit する。成功応答は error_id='' で、R60I0022 を返さない。画面は messageInfo.R60I0022 を自前で表示する。R60W0001 は init の message_info に含まれないため、文言を解決できない可能性がある。

## initEdit 端点（ヘッダ 3 モード）

`SES-API-006` / `api`

POST /api/R60SesModel/initEdit はヘッダマスタ項目モーダルを初期化する。mode 1=新規、2=複製、3=修正。mode 1 は空のヘッダを返し、ログイン会社・事業場を初期値にする。mode 2 は選択行を読み込み、業務キーを空にし、KSN_DAT と REV_NO をリセットする。mode 3 は選択行と KSN_DAT、REV_NO、DEL_FLG を返し、併せて子一覧を取得する。自動採番の可否（mode 1、区分 2、会社 0093 または 0452）も返す。mode 3 では mode='修正' を渡すが、応答モデルに mode が無いため値は落ちる。

## edit 端点（ヘッダ登録・修正）

`SES-API-007` / `api`

POST /api/R60SesModel/edit はヘッダを登録・修正する。mode 1=新規、2=複製、3=修正。新規・複製は重複チェック、イベントマスタ参照、REG_STS 判定の後、親を 18 列 INSERT し、子を一括登録する。修正は排他、イベント参照、復活チェック、緊急配信整合の後、10 列 UPDATE する。新規・複製は SEND_KBN='0'、REV_NO は開始値。修正は KSN_DAT=SYSDATE、REV_NO+1。成功応答は error_code、error_id、ses_mdl_cd のみで、message_id を返さない。

## delete 端点（ヘッダ論理削除）

`SES-API-008` / `api`

POST /api/R60SesModel/delete はヘッダを論理削除する。判定順は、対象存在（R60W0010）、排他（R60W0006）、イベントマスタ参照（R60W2019）、緊急配信対象の明細（R60W2007）、子の REG_STS（R60W2051）、被参照（R60W0017 flg=1）。通過後、参照テーブル 4 列、工場テーブル 4 列とフラグ、半製品・処方、親 9 列、子 8 列の順に論理削除し、I-Pro 連携と緊急配信を行って commit する。参照と工場の削除は KSN_KBN、KSN_STF_ID、REV_NO を更新しない。

## searchChild / initEditChild / getKonHmk

`SES-API-009` / `api`

POST /api/R60SesModel/searchChild は親の SES_MDL_CD を受けて子一覧を返す。0 件でもエラーにせず空一覧を返す。POST /api/R60SesModel/initEditChild は子モーダルを初期化し、mode 1/2/3 と子コード区分、単位、展開区分の 3 ドロップダウンを返す。会社 0093 と 0452 では設計どおりの初期値を設定する。POST /api/R60SesModel/getKonHmk は子コードの名称を取得し、取れない時は R60W0011 を ##1 / ##2 付きで返す。

## editChild / deleteChild

`SES-API-010` / `api`

POST /api/R60SesModel/editChild は子を登録・修正する。新規と複製は親存在、飲料社ルール、イベント参照、重複の順にチェックし、21 列 INSERT。修正は復活チェック、親存在、排他、イベント参照の順にチェックし、8 列 UPDATE する。POST /api/R60SesModel/deleteChild は存在、親存在、排他、イベント参照の後、8 列の論理削除を行い、親の REG_STS を再判定する。どちらも成功応答に message_id を含めない。

## 端点の無いモデル定義

`SES-API-011` / `api`

R60SesModelController.py には、端点を持たない Pydantic モデルが 2 組残っている。GetItemParams / GetItemRequest / GetItemData / GetItemResponse の 4 つ（1001-1115 行）と、GetKoCdNm 系（1675-1732 行）である。どちらも getKonHmk と役割が重複する。API 一覧を数えるとき、モデル定義の数ではなく @router.post の数で数える必要がある。

## イベントと端点の対応

`SES-API-012` / `api`

## 初期表示（L-SM-01）

`SES-LGC-001` / `logic`

R60SesModel の初期表示は、セッション確認とオンライン可否チェックの後、sim_kbn を検証する。空なら error_code='3'。事業場一覧（情報ID 000000375）、頁件数（000000089、既定は KOB_KMK_NM_10='D'、無ければ '10'）、工場ユーザーフラグ（000000412）、メッセージ 36 件を返す。ページ件数の既定は情報ID の個別項目名で決まり、画面の初期選択に使われる。

## 検索条件の組み立て（L-SM-02）

`SES-LGC-002` / `logic`

検索条件は、生産モデルコードを前方一致、生産モデル名を中間一致で加える。購入品目コード・名称と半製品コード・名称は、生産モデルの子を逆引きする条件になる。btn='0'（仕掛表示）の時だけ REG_STS='0' を加え、btn='1'（表示）では加えない。is_deleted が '1' でない時だけ DEL_FLG='0' を加える。この REG_STS の扱いは R60Plc と対照的で、設計と実装が一致している正例である。

## 件数チェックと上限（L-SM-03）

`SES-LGC-003` / `logic`

検索は同じ WHERE で COUNT(*) を先に取る。0 件は R60W0010、上限超過は R60W0005。上限は R60_GET_CODE_CHI_MEISAI_FNC('000000024','R60SesModel','0') で取得し、取得できない時は 500 を使う。上限超過時は data を空で返し、max_count を返して一覧を描画しない。R60W0005 の文言には 3000 と 3001 が直書きされており、情報ID の値と一致しない可能性がある。

## 並び順とページング（L-SM-04）

`SES-LGC-004` / `logic`

既定の並び順は DEL_FLG、SES_MDL_CD、ROWID。指定時は DEL_FLG、許可列 ASC または DESC、ROWID となり、副キーの SES_MDL_CD が落ちる。許可列は SES_MDL_CD と SES_MDL_NM の 2 つで、白名单外は既定へフォールバックする。ページングは OFFSET n ROWS FETCH FIRST m ROWS ONLY を使う。骨架の既定は ROWID 方式だが、移行案件の既存実装は OFFSET/FETCH である。

## 半製品の工場生産モデル判定（L-SM-05）

`SES-LGC-005` / `logic`

半製品が工場生産モデルに属するかを判定する。ビール社工場の会社コード 0001 と工場コード P030 が判定に現れる。工場生産モデルテーブル R60_KJO_SES_MODEL_M_TBL を参照し、対象の半製品が工場で生産されるかを決める。この判定は削除時の被参照チェックと登録時の整合チェックで使われる。会社・工場コードが直書きされているため、会社追加時はコード修正が必要になる。

## 購入品目・半製品からの生産モデル逆引き（L-SM-06）

`SES-LGC-006` / `logic`

購入品目コードまたは半製品コードを条件に、その子を持つ生産モデルを求める。実装は CONNECT BY NOCYCLE LEVEL <= 11 と CONNECT_BY_ISLEAF = 1 で親子を再帰解決する。巨大な IN リストを避けるための構造である。ただし LIKE 条件の値部分はエスケープされておらず、入力値が SQL 断片として混入し得る。階層上限 11 は生産モデルの深さの実測上限と読めるが、設計に明文はない。

## CSV ダウンロード（L-SM-07）

`SES-LGC-007` / `logic`

ダウンロードは直前の検索条件とソート順をそのまま使う。ビュー R60_SES_MODEL_M_VW を読み、R60CsvUtil で CSV 化する。削除条件は is_deleted == '0' の時だけ DEL_FLG を加える。search は is_deleted != '1' で加えるため、想定外の値では対象がずれる。WHERE 句は f-string で連結し、引用符の二重化は ses_mdl_cd にだけ行う。ファイル名は共通 CSV ユーティリティが返す。

## データ初期化（L-SM-08）

`SES-LGC-008` / `logic`

データ初期化は sim_kbn が '0'（通常環境）なら R60W0001 で拒否する。通過後、R60L550BBean.do_r60l550b() を SES と SES_MES の 2 回呼び、commit する。成功しても R60I0022 は返さず、error_id='' を返す。画面が完了文言を自前で表示する。通常環境で初期化を押すと、R60W0001 の文言が message_info に無いため解決に失敗し得る。

## ヘッダマスタ項目の初期化（L-SM-09）

`SES-LGC-009` / `logic`

ヘッダモーダルの初期化は 3 モード。新規は空のヘッダにログイン会社・事業場を初期値として入れる。複製は選択行を読み、親番と枝番を空にし、KSN_DAT と REV_NO をリセットする。修正は選択行と KSN_DAT、REV_NO、DEL_FLG を返し、併せて子一覧を取得する。自動採番の可否（新規、区分 2、会社 0093 または 0452）も応答に含める。修正時に mode='修正' を渡すが、応答モデルに mode が無いため値は落ちる。

## 半製品コード自動採番とダミー登録（L-SM-10）

`SES-LGC-010` / `logic`

自動採番は既存の子コード（半製品）から 4A0000 から 4Z9999 の範囲で最大値を求め、次の値を採番する。下 4 桁が 9999 なら英字を繰り上げる。枝番は 000 と 001 だけを使う。採番後、R60_HAN_SEIHIN_M_TBL にダミー半製品を INSERT する。INSERT は 40 列で、テーブルの 62 列のうち残りは DB 既定値に委ねる。REG_STS は '0' のまま（未確定）とする。枯渇時は R60W2019 の flg=1 を返す。

## ヘッダ新規・複製（L-SM-11）

`SES-LGC-011` / `logic`

ヘッダの新規と複製は、単項目チェック、重複チェック、イベントマスタ参照、REG_STS 判定の後、親を 18 列 INSERT し、子を一括登録する。重複は業務キーで判定し、既存なら R60W0014。SEND_KBN='0'、REV_NO は開始値、KSN_DAT は現在時刻。複製時は子コードが無いと R60W0032 で止まる。成功応答は error_code、error_id、ses_mdl_cd のみ。

## ヘッダ修正（L-SM-12）

`SES-LGC-012` / `logic`

ヘッダ修正は、排他チェック、イベントマスタ参照、復活チェック、緊急配信整合、REG_STS 判定の後、10 列 UPDATE する。排他は画面が保持する KSN_DAT と DB の KSN_DAT を比較し、不一致なら R60W0006。復活時に関連が未復活なら R60W0018、緊急配信対象に有効な明細が無ければ R60W2007。更新時は KSN_DAT=SYSDATE、REV_NO+1 とする。

## ヘッダ削除（L-SM-13）

`SES-LGC-013` / `logic`

ヘッダ削除は、対象存在、排他、イベントマスタ参照、緊急配信対象の明細、子の REG_STS、被参照の順にチェックする。通過後、参照テーブル 4 列、工場テーブル 4 列とフラグ、半製品・処方、親 9 列、子 8 列の順に論理削除し、I-Pro 連携と緊急配信を行って commit する。参照と工場の削除は KSN_KBN、KSN_STF_ID、REV_NO を更新しない。更新と削除は DEL_FLG や REG_STS で絞らず全行を対象にする。

## 明細一覧の表示（L-SM-14）

`SES-LGC-014` / `logic`

明細一覧は親の SES_MDL_CD を受けて子テーブルを検索する。0 件でもエラーにせず空一覧を返す。子コード名称は子コード区分に応じて、品目なら R60_Get_Hsh_Information_FNC、半製品なら R60_Get_KonHmk_Information_FNC で名称化する。一覧は送信、子コード区分、子コード、名称、所要量、単位、基準値、単位、調達対象外、展開区分、削除を返す。

## 明細マスタ項目の初期化と名称取得（L-SM-15 / L-SM-16）

`SES-LGC-015` / `logic`

明細モーダルの初期化は 3 モード。新規は空項目、複製は子コードだけ空にして数量とフラグを引き継ぎ、修正は選択行と KSN_DAT、REV_NO を返す。子コード区分、単位、展開区分の 3 ドロップダウンを返し、会社 0093 と 0452 では設計どおりの初期値を設定する。子コード検索は入力支援画面の戻り値で getKonHmk を呼び、名称を取る。取れない時は R60W0011 を ##1 / ##2 付きで返す。

## 明細新規・複製（L-SM-17）

`SES-LGC-016` / `logic`

明細の新規と複製は、親存在、単項目、飲料社ルール、イベントマスタ参照、重複の順にチェックし、21 列 INSERT する。親が削除済みなら R60W0019。飲料社工場ユーザーが非素材の購入品目を選ぶと R60W2050。イベントマスタ参照に失敗すると R60W2019。重複は子コード区分と子コードの組合せで判定し、既存なら R60W0014。

## 明細修正・削除（L-SM-18 / L-SM-19）

`SES-LGC-017` / `logic`

明細修正は、復活チェック、親存在、排他、イベントマスタ参照の順にチェックし、8 列 UPDATE する。復活時に関連が未復活なら R60W0018 か R60E0025、親が無ければ R60W0011、排他不一致なら R60W0006。明細削除は存在、親存在、排他、イベント参照の後、8 列の論理削除を行い、親の REG_STS を再判定する。

## 排他制御（L-SM-20）

`SES-LGC-018` / `logic`

R60SesModel は親と子の両方で KSN_DAT による楽観ロックを持つ。画面が initEdit または initEditChild で受け取った KSN_DAT を保持し、更新・削除時に送る。サーバは DB の KSN_DAT と比較し、不一致なら R60W0006 を返す。一致時は KSN_DAT を SYSDATE で更新し、REV_NO を +1 する。比較に一覧の値ではなく、モーダル初期化時の値を使う点が重要である。

## 被参照・復活・イベント参照チェック（L-SM-21 / L-SM-22）

`SES-LGC-019` / `logic`

被参照チェックはヘッダ削除時に R60W0017 の flg=1（親子）で判定する。復活チェックは修正・削除時に R60W0018 の flg 1 から 3 で対象を切り替える。子マスタが未確定（REG_STS='0'）なら R60W2051。イベントマスタ参照は登録・削除・自動採番の各所で行い、失敗時は R60W2019 の flg 1（枯渇）、2（登録）、3（削除・修正）を返す。同じ警告 ID でも flg で文言を差し替える。

## 単項目チェック 29 件（L-SM-23）

`SES-LGC-020` / `logic`

単項目チェックは 29 件。代表は、必須 R60W0009、緊急配信時の必須 R60W0012、削除時の必須 R60W0015、変更なし R60W0016、変更破棄 R60W0007、生産モデルコード桁 R60W0103、購入品目コード 6 桁 R60W0108、アイテム名称全角 20 桁 R60W0118、所要量・基準値の数値範囲 R60W0121、名称桁 R60W0131、子コード先頭と親番の不一致 R60W0031。エラー時は項目にフォーカスを戻す。半製品名称は本文 30byte、メッセージ引数 40 で食い違う。

## 項目間・DB 整合チェック 36 件（L-SM-24）

`SES-LGC-021` / `logic`

項目間・DB 整合チェックは 36 件。検索 0 件 R60W0010、上限超過 R60W0005、親子コード不在 R60W0011（flg 1/2/3）、重複 R60W0014、排他 R60W0006、関連データ必須 R60W0017（flg 1/2）、復活時未復活 R60W0018（flg 1-3）、親削除済み R60W0019、緊急配信必須 R60W0020、複製元に子なし R60W0032、緊急配信対象に有効明細なし R60W2007、イベント参照 R60W2019、飲料社非素材 R60W2050、子未確定 R60W2051、共通チェック null R60E0025、登録確認 R60A0003、削除確認 R60A0004 を扱う。

## メッセージ・確認フロー（L-SM-25）

`SES-LGC-022` / `logic`

登録前は R60A0003、削除前は R60A0004 の確認ダイアログを出し、キャンセルで中止する。戻る時は変更があれば R60W0007 で破棄確認をする。完了は登録・修正が R60I0001、削除が R60I0002、データ初期化が R60I0022。ただし更新系 API は message_id を返さず、画面が固定文言を表示する。dataInit も R60I0022 を返さず、画面が自前で表示する。

## ボタン活性制御（L-SM-26）

`SES-LGC-023` / `logic`

一覧画面のダウンロードと新規は初期状態で非活性、検索成功後に活性になる。ヘッダモーダルでは新規・複製で削除ボタンが非活性、修正で活性、削除済みの行では非活性。登録ボタンは新規モードでは常に活性、それ以外は権限区分 Y の時だけ活性になる。明細モーダルも同様で、新規・複製では削除ボタンが非活性、修正では活性である。コンポーネントのフラグ名は Enabled だが、実際は disabled 属性へバインドされ意味が反転している。

## REG_STS 判定と副次処理（L-SM-27）

`SES-LGC-024` / `logic`

REG_STS は、ヘッダの手入力では親番、枝番、生産モデル名、親コード区分の 4 項目が揃えば '1'、自動採番では生産モデル名と親コード区分の 2 項目で '1' になる。明細はダミー半製品なら常に '0'、通常の半製品と購入品目は必須 5 項目が揃えば '1'。登録・削除の確定時は処方マスタを更新し、緊急配信では SEND_STS='9' を設定し、ヘッダ削除時は I-Pro 連携を行う。順序は排他、イベント参照、被参照、本体更新、外部連携の順で固定。

## 状態定数と情報ID（L-SM constants）

`SES-LGC-025` / `logic`

R60SesModel の状態定数は、オプション区分 1=アイテム、2=半製品、3=原材料、mode 1=新規、2=複製、3=修正、search_btn 0=仕掛表示、1=表示、is_deleted 1=削除を含む、REG_STS 0=未確定、1=確定、SEND_STS 9=緊急配信。情報ID は、上限件数 000000024、送信ステータス 000000057、親コード区分 000000091、削除フラグ 000000063、頁件数 000000089、工場ユーザー 000000412、事業場一覧 000000375 を使う。PGM_ID は R60SesModel。

## メッセージ台帳の概観

`SES-ERR-001` / `error`

R60SesModel のメッセージは 3 箇所に分散している。その他メッセージシートは 13 行で 8 ID、単項目・項目間チェックが参照するのは 33 ID、実装は 36 ID を取得し 37 ID を参照する。完全一致しない。その他メッセージだけを見て実装を照合すると、チェック系の文言の欠落を見落とす。実装が参照する 37 ID のうち R60W0001 だけが取得されていない。

## 検索のメッセージ

`SES-ERR-002` / `error`

検索では結果 0 件なら R60W0010、件数が上限を超えたら R60W0005 を返す。上限は情報ID 000000024 から取得し、取得不能時は 500。上限超過時は一覧を描画しない。R60W0005 の文言には 3000 と 3001 が直書きされており、情報ID の現在値と一致しない可能性がある。検索条件の入力エラーは単項目チェック側で止める。

## ヘッダ登録・修正のメッセージ

`SES-ERR-003` / `error`

ヘッダ新規は単項目（W0009、W0016、W0103、W0131、W0012、W0015）の後、W0011（コード不在）、W0032（複製元に子なし）、W2019 flg=2（イベント参照）、W0014（重複）、W2051（子未確定）の順にチェックする。ヘッダ修正は W0006（排他）、W0011、W2019 flg=3、E0025 または W0018（復活）、W2007（緊急配信対象）、W2051、W0017 または W0020 の順である。

## 削除のメッセージ

`SES-ERR-004` / `error`

ヘッダ削除は W0010（対象なし）、W0006（排他）、W2019 flg=2（イベント参照）、W2007（緊急配信対象に有効明細なし）、W2051（子が未確定）、W0017 flg=1（親子被参照）の順に止める。すべて通過した時だけ、参照、工場、半製品・処方、親、子の順に論理削除する。明細削除は W0011、W0006、W2019 flg=3 の順である。

## 明細登録・修正のメッセージ

`SES-ERR-005` / `error`

明細新規は W0019（親が削除済み）、W0011（コード不在）、W2050（飲料社工場の非素材）、W2019（イベント参照）、W0014（重複）の順にチェックする。明細修正は W0018 または E0025（復活）、W0011、W0006（排他）、W2019 の順である。子コード検索で名称が取れない時は W0011 を ##1 / ##2 付きで返す。

## 確認・完了メッセージ

`SES-ERR-006` / `error`

登録前確認は R60A0003、削除前確認は R60A0004、変更破棄は R60W0007。完了は登録・修正が R60I0001、削除が R60I0002、データ初期化が R60I0022。ただし更新系 API は message_id を返さず、画面がモードに応じて R60I0001 または R60I0002 を固定表示する。dataInit も R60I0022 を返さず、画面が自前で表示する。

## error_flg の意味

`SES-ERR-007` / `error`

同じ警告 ID でも画面が文言を差し替えるため、error_flg が必須である。R60W0011 は flg 1=アイテム、2=半製品、3=購入品目。R60W0017 は flg 1=親子、2=生産・工場。R60W2019 は flg 1=自動採番の枯渇、2=イベント参照（登録時）、3=イベント参照（削除・修正時）。R60W0018 は flg 1 から 3 で対象を切り替える。メッセージ ID だけを追うと、どの文言が出るか分からない。

## 取得されないメッセージ R60W0001

`SES-ERR-008` / `error`

R60W0001 は dataInit で sim_kbn が '0' の時に返されるが、init の message_info 36 件に含まれない。画面が warning の文言を引けない可能性がある。設計のその他メッセージシートにも記載がない。不具合候補として扱い、通常環境でデータ初期化を押した時の挙動を確認する必要がある。

## 単体テスト仕様の全体

`SES-TST-001` / `test`

R60SesModel の単体テスト仕様兼結果は、ヘッダ上 760 項目、FP 26、バグ 0。テストレベルは画面単位の単体テストで、全件 OK で終了している。FP 26 の内訳と定義は本文に無く、ファンクションポイントか工程管理値かは未確認である。仕様書が『兼結果』であり、期待値と実施結果が同一ファイルにあるため、結果欄が期待値の転記になっていないかは原本の列構成を確認する必要がある。

## 760 セルと実項目 679 の差

`SES-TST-002` / `test`

760 は節の小計行を二重に数えている。実テスト項目は 679。760 = 679 + 53（B5 小計）+ 21（B21 小計）+ 7（B25 小計）である。B5 の小計 53 は配下の子 48 と一致せず、5 件の差がある。この差の原因は未確定。対外説明に 760 と 679 のどちらを使うかも未確定である。項目数を数えるときは、小計行を除いた実項目で数える。

## 教材としての再利用パターンと反パターン

`SES-REV-010` / `review`

再利用できるパターンは、主従 4 画面、1 モーダルで新規・複製・修正の 3 モード、自動採番とダミーマスタ登録を 1 関数にまとめること、CONNECT BY で親子を再帰解決すること、1 テーブルにつき操作パターン別の移送表を分けること、REG_STS を必須項目の充足で判定すること、排他、イベント参照、被参照、更新、外部連携の順序を固定すること、表示は REG_STS で絞らず仕掛表示だけ絞ること。反パターンは、小計行を項目数に含めること、コード値をエスケープせず SQL に埋め込むこと、死んだ Service とモデルを残すこと、返すメッセージ ID を取得しないこと、顧客会社コードを直書きすること、BP に疑問メモを残すこと、API が完了メッセージを返さず画面が固定文言を持つこと、Enabled で disabled を制御すること。
