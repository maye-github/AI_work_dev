## R60Ssk / 検索条件の単項目チェック（R60W0009 / R60W0106 / R60W0131）

## R60Ssk / 更新専用という第一命題

`R60Ssk:review:update-only` / `review`
R60Ssk は『部署マスタメンテナンス』という名称だが、新規作成も論理削除も提供しない。根拠は 3 つ。項目移送表の登録・削除列に ○ が 1 つも無いこと、検索画面の新規ボタンとマスタ項目画面の削除ボタンが初期値 非活性であること、イベント 16 件に新規・削除が無いこと。前提条件『IDM からのデータ受信が完了していること』がこの設計を説明する。名称から新規・削除を想定すると、設計に無い機能を作ってしまう。

## R60Ssk / 設計書自身の矛盾と欠番

`R60Ssk:review:contradictions` / `review`
設計書には次の矛盾がある。REG_STS の本文は 4 項目判定で 0 を設定すると書くが、同じセルに『定数 REG_STS_ON を設定しているのでこの設定は無効』という実装メモが混在する。組織ユニットはチェック内容が『半角英数字以外』、メッセージが『半角数字』で矛盾する。表示処理の番号は 1・2・4・5・6・7・8 で 3 が欠番。いずれも設計書だけでは正否を決められず、人への確認事項になる。

## R60Ssk / ソート列の名称と DB 列の対応が不明

`R60Ssk:review:sort-ambiguity` / `review`
ソートは会社・事業場組織ユニット・組織ユニット：コードの 3 列が可能と書かれるが、イベント一覧の処理概要は『標準仕様参照』だけで、DB 列との対応が無い。さらに検索シートとマスタ項目シートで、項目名称とエンティティ項目の対応が入れ替わって見える。実装の許可項目は CMP_CD・SSK_UNIT・JIG_SSK_UNIT。指定ソート時は既定の副キーが落ち、ROWID でしか順序を担保しない。

## R60Ssk / download の SQL 連結

`R60Ssk:review:security` / `review`
download は cmp_cd・ssk_unit・sei_nm を WHERE 句へ文字列連結している。同じファイルの search は bind パラメータを使っており、安全度が異なる。共通 CSV ユーティリティが WHERE 文字列を受け取る設計であることが原因。セキュリティ方針に関わるため骨架側では修正せず、人（ユーザー）の裁定事項として残す。

## R60Ssk / 教材としての強みと注意

`R60Ssk:review:teaching` / `review`
