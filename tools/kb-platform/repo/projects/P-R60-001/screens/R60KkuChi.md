### 5.4 検索（イベント 9）

  から動的に決める。パターンごとに返す列が変わる仕組み。
- （実装）ソートは `ALLOWED_SORT_FIELDS = {KEY_KMK_1..6}` の白名单。外は固定ソートへフォールバック。

### 5.6 削除（イベント 37、r479-r537）

1. **単項目チェック**（規格値の 5 項目、`R60W0121`）。
2. **削除確認メッセージ** `R60A0004`（キャンセルなら中断）。
3. **排他チェック**：更新時刻不一致かつ更新区分オンライン → `R60W0006`。
4. **削除処理**：`項目移送表(DB)` の (削除) 列に従う。
5. **完了メッセージ** `R60I0002`。
6. 画面を閉じ、検索結果を再表示。

- （実装）排他 → メッセージ ID 存在チェック（`R60W0010`）→ `update()` → commit。
- （実装）`update()` は **Y（削除）列の一式**（規格値 11 列＋DEL_FLG＋管理 5 列）を書く。
  設計の (削除) 列と一致する（【実測】`37` r23-r46）→ **良い対比**。
- （実装）`A0004`／`I0002` は **画面側が messageInfo から表示**する。サーバーは返さない。

### 5.8 戻る（イベント 39）

### 5.9 排他の定義（設計 r525-r527 / 実装 `haita_check`）
