## 5. 業務処理説明（【文書】`21_業務処理説明` 1,935 行）

### 5.1 イベント共通

1. **セッション情報存在チェック**：無ければセッション情報エラー画面へ。
2. **オンライン利用可否フラグチェック**：NG ならオンライン制御エラー画面へ。

【実測】12 端点はすべて先頭で `r60util.chk_onl_flg()` を呼ぶ。

### 5.2 検索（イベント No6 / No7 / No18 / No19）

1. **単項目チェック**：コードの文字種・桁、名称の桁（§5.6）。
2. **WHERE の生成**
   - 生産モデルコード＝前方一致、名称＝中間一致
   - `btn='0'`（仕掛表示）の時だけ `REG_STS='0'`
   - `is_deleted != '1'` の時 `DEL_FLG='0'`
   - 購入品目コード・半製品コードは **生産モデルの逆引き**（§5.3）
3. **件数取得**：同じ WHERE で `COUNT(*)`。0 件 → R60W0010、上限超過 → R60W0005。
   - 上限は `R60_GET_CODE_CHI_MEISAI_FNC('000000024','R60SesModel','0')`、取得不能時 **500**。
4. **抽出列**：`R60_GET_SELECT_COLUMN_FNC('R60_SES_MODEL_M_TBL','L')`。
5. **ソート**
   - 既定：`DEL_FLG, SES_MDL_CD, ROWID`
   - 指定：`DEL_FLG, {SES_MDL_CD|SES_MDL_NM} {ASC|DESC}, ROWID`
   - 白名单外は既定へフォールバック。**指定時に副キーが落ちる**（D-SM-07）。
6. **ページング**：`OFFSET {n} ROWS FETCH FIRST {m} ROWS ONLY`（D-SM-08）。
7. **ボタン活性**：検索成功後にダウンロード・新規を活性化する。

> **★R60Plc と逆の正例**：R60Plc は「表示＝確定のみ」の設計に実装が追随していなかった（D-PL-07）。
> 本画面は「**表示は REG_STS で絞らない／仕掛表示だけ絞る**」という設計に実装が一致している。

### 5.3 購入品目・半製品からの生産モデル逆引き

- 半製品・購入品目を条件に、**その子を持つ生産モデル**を求める。
- 【実測】`CONNECT BY NOCYCLE LEVEL <= 11` と `CONNECT_BY_ISLEAF = 1` で親子を再帰解決する。
- 巨大な `IN` リストを避けるための構造である（`L-SM-06`）。
- 【差異】コード値の LIKE 条件が**エスケープされていない**（`KO_CD LIKE '値%' ESCAPE '\'` の値部分）→ D-SM-05。

### 5.4 ヘッダマスタ項目モーダルの初期化（イベント No9 / No11 / No16）

1. **mode 1（新規）**
   - 空のヘッダを返す。ログイン会社・事業場を初期値にする。
2. **mode 2（複製）**
   - 選択行を読み込み、業務キー（親番・枝番）を空にする。
   - `KSN_DAT` / `REV_NO` を**リセット**する（複製は新規扱い）。
3. **mode 3（修正）**
   - 選択行を読み込み、`KSN_DAT` / `REV_NO` / `DEL_FLG` を画面に保持する。
   - 併せて子一覧を取得する（`searchChild`）。
4. **自動採番の条件**を返す（mode 1 ＋ 区分 2 ＋ 会社 0093/0452）。
5. 【差異】mode 3 では `InitEditHeaderData` に `mode='修正'` を渡すが、
   **モデルに mode が無いため応答から落ちる**（D-SM-21）。

### 5.5 明細一覧（イベント No10 / No18）

1. 親の `SES_MDL_CD` を受ける。
2. 子テーブル `R60_SES_MODEL_MES_M_TBL` を親コードで検索する。
3. 0 件でもエラーにせず**空一覧**を返す。
4. 子コード名称は区分に応じて関数で名称化する。

### 5.6 明細マスタ項目モーダルの初期化（イベント No12 / No16 / No27）

1. **mode 1（新規）**：子区分・子コード・所要量・基準値・フラグの空項目。

### 5.11 登録ステータス判定（`REG_STS`）

| 対象 | `REG_STS='1'` になる条件 |
|---|---|
| ヘッダ（手入力） | 親番・枝番・生産モデル名・親コード区分の **4 項目が全て入力** |
| ヘッダ（自動採番） | 生産モデル名・親コード区分の **2 項目が入力** |
| 明細（ダミー半製品） | **常に `'0'`**（未確定のまま） |
| 明細（通常の半製品） | 必須 5 項目が充足 |
| 明細（購入品目） | 必須 5 項目が充足 |

- 子に未確定（`REG_STS='0'`）が残る親は、削除時に R60W2051 で止まる。

### 5.12 自動採番とダミーマスタ登録（`auto_number_hsh_cd`）

1. 既存の子コード（半製品）から **`4A0000`〜`4Z9999`** の範囲で最大値を求める。
2. 次の値を採番する（下 4 桁の 9999 → 英字繰上げ）。
3. **`R60_HAN_SEIHIN_M_TBL` にダミー半製品を INSERT**（**40 列**）。
   - テーブルは 62 列だが、INSERT するのは 40 列。残りは DB 既定値。
   - `REG_STS='0'` / `SEND_STS='0'` / `DEL_FLG='0'` / `REG_PGM_ID='R60SesModel'` 等。
4. 枯渇時は **R60W2019(flg=1)**。

> **★「62 列表だから 62 列 INSERT」と読むと誤る**。移送表の更新対象列と INSERT 列は別である（D-SM-13）。

### 5.13 データ初期化（イベント No17）

1. `sim_kbn == '0'`（通常環境）なら **R60W0001** で拒否。
2. `R60L550BBean.do_r60l550b()` を **2 回**呼ぶ（`SES` → `SES_MES`）。
3. `commit`。
4. 【差異】成功時は `error_id=''` を返し、**R60I0022 を返さない**。
   画面が `messageInfo.R60I0022` を自前で表示する（D-SM-23 と同型）。
   【差異】`R60W0001` は init の message_info に含まれない（D-SM-10）。

### 5.14 副次処理

| 処理 | 契機 | 内容 |
|---|---|---|
| 処方マスタ更新 | ヘッダ・明細の登録／削除 | `R60_SYOHO_M_TBL` を更新（6 列）。`sim_kbn != '0'` の時だけ |

| I-Pro 連携 | ヘッダ削除 | 外部連携 |

- **副次処理の順序は「排他 → イベント参照 → 被参照 → 本体更新 → 外部連携」**で固定されている。

### 5.15 ダウンロード（イベント No15）
