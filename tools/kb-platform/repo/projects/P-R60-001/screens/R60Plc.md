## 5. 業務処理説明（【文書】`13_業務処理説明` 354 行）

### 5.1 イベント共通

1. **セッション情報存在チェック**：無ければセッション情報エラー画面へ。
2. **オンライン利用可否フラグチェック**：NG ならオンライン制御エラー画面へ。

【実測】6 端点はすべて先頭で `r60util.chk_onl_flg()` を呼ぶ。

### 5.2 検索（イベント No5 / No6）

1. **単項目チェック**：コードの文字種・桁数、名称の桁数など（詳細は §5.4）。
2. **WHERE の生成**
   - 会社・事業場・エリア・グループ・タイプ＝完全一致
   - ロケーションコード＝前方一致、名称＝中間一致
   - 削除含む＝未チェックなら `DEL_FLG='0'`
   - **仕掛表示（`search_btn='0'`）だけ `REG_STS='0'` を加える**
   - **表示（`search_btn='1'`）は `REG_STS` を加えない** → D-PL-07
3. **件数取得**：同じ WHERE で `COUNT(*)`。0 件 → R60W0010、上限超過 → R60W0005。
4. **抽出列**：`R60_GET_SELECT_COLUMN_FNC('R60_PLC_M_TBL', 'L')` 相当。
5. **ソート**
   - 既定：`DEL_FLG, CMP_CD, JIG_CD, PLC_CD, ROWID`
   - 指定：`DEL_FLG, {CMP_CD|JIG_CD|PLC_CD} {ASC|DESC}, ROWID`
   - 白名单外は既定へフォールバック。
   - 【差異】指定時に副キーが落ちる（D-PL-10）。
6. **ページング**：頁件数で分割し、総件数と頁一覧を返す。
7. **ボタン活性**：検索成功後にダウンロード・新規を活性化する。

> **★表示ボタンの扱いが設計と実装で違う。**
> 設計は「表示＝確定のみ」だが、実装は表示時に `REG_STS` で絞らない（D-PL-07）。
> **未確定データが一覧に現れる**ため、業務上の見え方が変わる。**どちらが正かは未確定。**

### 5.3 マスタ項目モーダルの初期化（イベント No12 / No13 / No17）

1. **mode 1（新規）**
   - 情報ID `295 / 296 / 297 / 299 / 300 / 301 / 302 / 303 / 420` から初期値を取得する。
   - 会社・事業場はログインユーザーの所属を初期選択にする。
2. **mode 2（複製）**
   - 選択行を業務キーで読み込む。
   - ロケーションコードだけ空にし、名称・容量・フラグ類は引き継ぐ。
3. **mode 3（修正）**
   - 選択行を読み込み、コードを編集不可にする。
   - `KSN_DAT` / `REV_NO` / `DEL_FLG` を画面に保持する。
4. **ドロップダウン 17 種**を返す（情報ID 119 / 117 / 158 / 159 / 123 / 124 / 125 / 121 / 120 /
   127 / 126 / 118 / 157 / 160 / 418 / 419）。
5. 会社・事業場を変更すると、エリア・グループのリストを再生成する（フロント処理）。

### 5.6 削除（イベント No23）

1. **排他チェック**（`KSN_DAT`）。
2. **被参照チェック**：`R60_CHECK_PLC_INFO_FNC(業務キー)`。
3. **論理削除 UPDATE**：`DEL_FLG='1'`、`SEND_STS='0'`、`KSN_KBN='1'`、
   `KSN_DAT=現在時刻`、`REV_NO+1`。更新列は **33 列**。
4. **REG_STS を再判定**する。
5. 成功時、バックエンドは **R60I0002**（削除しました。）を返す。

> **★画面は R60I0001（登録しました。）を表示する**（D-PL-08）。
> 応答メッセージを使わず、フロントが固定文言を出している。**削除の完了通知が誤っている。**

### 5.7 登録（イベント No24）

| mode | 処理 | チェック |
|---|---|---|
| 1 新規 | INSERT（41 列） | 重複 → 必須 → 登録確認 |
| 2 複製 | INSERT（41 列） | 重複 → 必須 → 登録確認 |
| 3 修正 | UPDATE（33 列） | 排他 →（削除チェック時）被参照 → 登録確認 |

- 新規・複製：`SEND_KBN='0'`、`REV_NO=開始値`。
- 修正：`REV_NO+1`、`KSN_DAT=現在時刻`。
- **登録系 5 列と `SEND_KBN` は UPDATE 対象外**。
- 成功時は **R60I0001**（登録しました。）。

### 5.8 登録ステータス判定（`set_reg_sts`）

- **基本 18 項目**がすべて埋まれば `REG_STS='1'`、欠ければ `'0'`。
- **ロケーション属性区分 = '02'（タンク）** の時は、さらに **6 項目**を必須に加える。
- 6 項目：検尺管理区分 / 検尺検定区分 / 検尺単位 / 最大深さ / 開始検定深さ / 仮想タンク区分。
- 【実測】`R60PlcController.py:3035-3076`。

### 5.9 ダウンロード（イベント No16）

1. 直前の検索条件・ソート順でデータを取得する。
2. ヘッダ：`R60_GET_SELECT_COLUMN_FNC('R60_PLC_M_TBL', 'H')`。
3. 明細：同 `'D'`。
4. ファイル名：`R60CsvUtil.get_csv_name()`。
5. 【差異】**WHERE を文字列連結**で組み立てる（`search` は bind）→ D-PL-09。
